# pmem

**插拔式、托管式的 AI 项目记忆系统**

让 AI 编程助手记住项目里踩过的坑、排除过的方向和做过的决定，<br>
并在下次改代码前自动想起来。

## 为什么用 pmem

- 🔌 **插拔式**：一条 `pmem init` 接入任何项目，不改业务代码；不想用了，删掉它生成的配置即可。
- 🤖 **托管式**：查记忆、写记忆、忘查时拦截、改完没记时提醒，全部由 AI 和 Hook 自动完成。
- 👥 **团队共享**：记忆是仓库里的 Markdown 文件，随代码提交，队友拉代码就有；不需要服务器，不上传任何数据。
- 📉 **越用越收敛**：记忆越积累，AI 越准（少犯同样的错）、越快（老问题不用从头排查）、越省 token，项目越到后期维护越明显。

## 日常使用：和以前完全一样

> **接入后照常提需求、修 bug、问问题即可。**
> 不需要记命令，不需要手动查或写记忆，也不需要改变任何使用习惯。

你照常对话时，pmem 在背后自动做这些事：

- **改前先查**：AI 要改某个文件，pmem 找到它所属的业务模块（如 `gameplay.Jigsaw`），把以前的根因、排除过的方向和风险交给 AI。
- **问答也查**：AI 读到某个模块的代码时，自动附上该模块现行结论的摘要。
- **改后记录**：确认根因、排除某个方向、改完验证通过时，AI 自动按模块写一条记忆。
- **自动兜底**：AI 忘了查就去改，会被拦下直到查过为止；改了代码却没记，回合结束时提醒一次。
- **不用过期结论**：记忆关联的代码后来改过或被删了，会自动标出“需核实”。

## 快速接入（约 5 分钟，每个项目一次）

```bash
# 1. 安装（每人一次）
uv tool install "pmem[embed] @ git+https://github.com/mry-ship/pmem"

# 2. 在项目根目录接入
pmem init --type game            # 项目类型：game / app / backend / generic
```

3. **打开开关**：Cursor 设置 → MCP → 启用 `pmem`（Claude Code、Codex 首次打开项目时批准即可）。
4. **划分模块**：对 AI 说“按 pmem-bootstrap 技能划分模块”，确认它给出的表格。
5. **提交**：运行 `pmem doctor` 自检，然后把 `.memory/` 和 `.cursor/` 提交到版本库。

队友拉代码后，只需要做第 1 步和第 3 步。需要 [uv](https://docs.astral.sh/uv/)（Python 包管理工具）和 Python 3.10 以上。

## 可选操作（都不是必须）

不做这些，pmem 照样正常工作。需要时再用：

| 想做什么 | 怎么做 |
|---|---|
| 让队友也看到新记忆 | 提交代码时把 `.memory/` 一起提交（建议） |
| 这次对话不用记忆 | 对 AI 说“跳过记忆”；说“恢复记忆”撤销 |
| 记忆多了，合并零碎记忆 | 对 AI 说“按 pmem-compact 技能合并记忆” |
| 换个说法搜不到 | 对 AI 说“按 pmem-normalize 技能整理同义词”（如“闪退 / 崩溃”） |
| 新增了业务模块 | 在 `.memory/modules.yaml` 里加模块和它的路径 |
| 体检 | `pmem doctor`：提示没提交的记忆、可以合并的议题 |
| 看收益 | `pmem report`：命中率、避坑次数、跨人复用 |
| 通读全部结论 | 打开 `.memory/wiki/index.md`，每个模块一页，写入记忆后自动更新 |
| 升级 | `uv tool upgrade pmem`，再在项目里运行一次 `pmem init`（不会覆盖已有配置） |

<details>
<summary><b>一条记忆长什么样</b></summary>

一条记忆就是一个文件，例如 `.memory/entries/gameplay.Jigsaw/01M4X6AZN6N1AX9M6E6P34SRX4.md`：

```markdown
---
module: gameplay.Jigsaw
entity: Reward
kind: exclusion          # conclusion 结论 / exclusion 排除项 / correction 更正 / risk 风险 / decision 决定
anchors: [Assets/Game/Jigsaw/JigsawReward.cs#Claim]
---
断线重连时奖励重复发放：根因是服务端 Claim 没有按关卡做幂等校验，不要在客户端去重。
```

## 效果

**和没有记忆系统相比**（一个游戏项目的真实对话，改过代码的对话：没有记忆时 122 个，用上一代记忆系统后 62 个）：

| 指标 | 没有记忆 | 有记忆（上一代系统） | pmem（本系统） |
|---|---|---|---|
| 被用户纠正的比例 | 基准 | **下降 54%～69%** | 待实测；正确结论排进前 3 由 6 个提到 16 个 |
| 每次改代码的耗时 | 基准 | **下降 36%～44%** | 待实测；单次检索由 300～400 毫秒降到 9 毫秒 |
| 读写 token 总量 | 基准 | **下降 18%** | 待实测；自身开销见下文“越用越收敛” |
| 长对话全程不回退 | 27% | **52%** | 待实测；终端写命令也拦，事后还会比对 |

前两列是上一代记忆系统上线前后的对比（前后对比，不是对照实验）。pmem 在它的基础上全面加强，这组数字可以看作**保守参考**；pmem 列可用 `pmem bench` 做对照实验后补上。

**pmem 比上一代强在哪**（同一项目 853 条真实记忆离线回放）：

| 指标 | 上一代系统 | pmem |
|---|---|---|
| 正确结论排进前 3（18 个人工核对的查询） | 6 个 | **16 个** |
| 写进去后被悄悄删掉的记忆 | 约 19% | **0** |
| 单次检索耗时 | 300～400 毫秒 | **中位 9 毫秒** |
| 忘了查就改 | 只拦编辑工具，终端命令可绕过 | **编辑工具和终端写命令都拦，事后还会比对** |
| 团队共享 | 个人机器上的向量库，换嵌入模型曾丢约 160 条 | **随仓库提交，队友拉代码就有** |
| 接入 | 单人单项目、手工配置 | **`pmem init` 一条命令，支持 Cursor / Claude Code / Codex** |

## 越用越收敛：准确性、耗时与 token

**开销固定，收益随积累增长：项目越到后期维护，AI 越准、越快、越省 token。**

| 阶段 | 情况 | 准确性与耗时 | token 收支 |
|---|---|---|---|
| 刚接入 | 记忆还少，大多查不到东西 | 和没有记忆时差不多 | 小幅净增（每个对话约 3000～5000） |
| 积累期 | 常改的模块有了根因、排除项和风险 | 同样的错开始不再犯，排查变短 | 少走的弯路开始抵消开销 |
| 维护期 | 老问题复发、改历史逻辑、换人接手 | 直接拿到根因和结论，返工明显减少 | 一条几百 token 的结论，顶掉一次重新读代码、重新排查、重试已排除方向 |

**为什么会收敛**：
- **开销不随记忆变多而增长**：AI 不直接读记忆文件，每次只拿检索返回的前几条（默认 5 条），被替代的旧结论不返回。853 条记忆的项目，单次开销和几十条时相近。
- **收益随记忆变多而增长**：踩过的坑、排除过的方向、更正都留了下来，同样的错不再犯第二次；老问题直接拿到结论，不用重新读代码、重新排查。
- **记忆越用越精**：零碎记忆可合并（实测 13 条约 2500 字合并为 2 条约 1150 字），同义叫法会归一，检索返回的都是现行结论。

**收敛的前提**（pmem 已内置对应机制，偶尔配合即可）：
- **记忆要准**：代码改了而记忆没跟上，会给出过期结论。pmem 自动标“需核实”，并要求 AI 核对后确认或更正。
- **不能太零碎**：同一议题零碎记忆太多会互相挤占、给出前后矛盾的阶段结论。`pmem doctor` 会提示，说一句“按 pmem-compact 技能合并记忆”即可。

收敛有下限：最终趋向“真正的新工作量”，不会无限下降；全新功能、还没有记忆的模块享受不到。

阶段趋势按机制推断，佐证是上一代系统的前后对比（被纠正比例 −54%～69%、改代码耗时 −36%～44%、token −18%），pmem 自己的分阶段数据还没测；接入后可定期用 `pmem report` 看本项目“用到记忆”和“未用到”两组对话的对比。

<details>
<summary><b>常用命令</b>（日常不需要，排查或自己查看时用）</summary>

```bash
pmem search --path <文件>              # 查某个文件所属模块的记忆
pmem search --module <模块> "关键词"    # 按模块和关键词查；加 --brief 每条一行
pmem list                              # 模块和记忆数量
pmem doctor                            # 体检
pmem report                            # 本机收益报告
pmem wiki                              # 生成浏览用的模块 Wiki
pmem format --apply                    # 把旧记忆里一整行的长正文断行（新写入的会自动整理）
```

全部命令、配置项和常见问题见 [使用手册](https://mry-ship.github.io/pmem/pmem-guide.html)。

<details>
<summary><b>已知限制</b></summary>

- Claude Code、Codex 的接入只做过模拟测试，还没在真实会话里跑过。
- Cursor 不允许在提问时注入内容，所以纯问答（不读代码）的记忆审查发生在回合结束时：AI 先回答，再被要求查记忆并修正。Claude Code 可以在提问时直接附上摘要。
- 收益报告只统计本机数据。
- 终端里的写操作靠解析命令识别：重定向、`Set-Content`、`cp`/`mv`、`git checkout/restore/apply`、`python -c`、套一层的 `powershell -Command`/`cmd /c`/`bash -c`、先 `cd` 再写相对路径，以及所运行脚本里的字面路径都能认出。脚本里拼接出来的路径、格式化工具和 `git stash`/`reset` 这类命令事前认不出：执行后比对未提交文件（Git、SVN 都支持），改到没查过的模块时立即提醒补查（只能事后提醒，拦不住）。仓库大到单次比对超过 1 秒时，这项比对暂停 24 小时。
- 队友没装 pmem 时，闸门和审查都不生效（Hook 起不来，按设置放行，不会卡住）；新对话开始时会提示 Agent 让用户先安装。
- 按函数判断过期只支持 Git；SVN 和找不到函数时按文件判断。
- Windows PowerShell 5 里把 pmem 输出再接给 `Select-String` 等命令会乱码（它按 GBK 解码），直接看输出或用 `--brief`。

</details>
