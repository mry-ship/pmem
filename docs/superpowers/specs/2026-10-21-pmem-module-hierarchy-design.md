# pmem 多段模块名（父子模块）设计

日期：2026-10-21 状态：已实现（四个阶段），与原稿的差异见 3.6 的“实现调整”

## 1. 背景与目标

项目的业务结构常常是“模块 → 子模块 → 共用基类”，例如广告：公共广告逻辑之下有 4 个 SDK，每个 SDK 又有自己的渠道，iOS 与 Android 打入包体的 SDK 不同。
现在的模块名固定两段（`大类.模块名`），表达不了这种包含关系：

- 子模块只能做成平级模块，查子模块时看不到父模块里“所有 SDK 都适用”的教训；
- 健康检查把父子模块报成“疑似重复”，又没有办法标记“不是重复”；
- `modules.yaml` 里虽然能写 `parent` 字段，但除了改名时同步改写，系统没有任何地方用到它。

目标：

1. 模块名支持最多 4 段，父子关系直接由名字表达：`system.Ads.AdMob` 的父模块是 `system.Ads`。
2. 查子模块时自动带上祖先模块的教训，且不挤掉子模块自己的记忆。
3. 写入、闸门、健康检查、同步、迁移、Wiki 都认识父子关系。
4. 名字看不出的深层关联，用 `modules.yaml` 里显式的 `related` 字段登记。

不做：

- 跨大类的父子关系（子模块一律继承父模块的大类）；
- 超过 4 段的模块名；
- 把平台、渠道、节日变体这类交叉维度编进模块树（继续用 applies、entity、variants 表达）。

## 2. 现状（改动分析）

### 2.1 模块名的解析

| 位置 | 现在的行为 | 多段名下的问题 |
|---|---|---|
| `core/registry.py` `_NAME_RE`、`is_module_id` | 模块名部分只允许字母数字下划线，不能含点 | 需放开为最多 3 段，每段各自校验 |
| `Module.name`（`split(".", 1)[1]`） | 取第一个点之后的全部 | 会得到 `Ads.AdMob`，短名索引和名称匹配都按它算 |
| `resolve_module` | 不带点按短名查；带点按 `大类.名字` 解析；未登记且大类合法时允许写入（自动成为未登记模块） | 需定义多段短名、未登记多段名的规则 |
| `name_patterns` | 文字里提到模块名或不带点的别名就算提到 | 短名应为最后一段 |
| `from_dict` | 只按第一个点拆大类，**不校验名字格式** | 对旧版兼容有利，见 2.4 |

按点号拆模块名的写法共 22 处，分布在 7 个文件：`core/registry.py`（8）、`catalog/migrate.py`（4）、`catalog/sync.py`（3）、`metrics/health.py`（2）、`generate/wiki.py`（1）、`cli/import_cmd.py`（1）；`scan/files.py` 的 3 处是拆文件扩展名，与本次无关。
其中取大类的写法（`split(".", 1)[0]`）在多段名下仍然正确，需要改的是取“名字部分”的写法。

### 2.2 存储

记忆文件在 `.memory/entries/<模块名>/<id>.md`，模块名整体作为一层目录名（如 `entries/system.Ads.AdMob/`），所有遍历都用 `*/*.md`。
多段名不改变目录结构，无需迁移。路径长度：4 段名一般在 40 个字符以内，不会成为 Windows 260 字符限制的主因，doctor 加一条检查即可。

### 2.3 用到模块名的功能

| 功能 | 位置 | 现在 | 需要的变化 |
|---|---|---|---|
| 检索 | `index/store.py` `search`（第 289 行） | 只取模块名完全相同的记忆 | 带上祖先模块的教训，限额、降权 |
| 检索结果 | `service/search.py` `_search` | 返回 `related`（共享代码、正文提及） | 增加父子信息；`related` 排除自己的祖先和后代 |
| 模块列表 | `service/search.py` `list_modules` | 平铺 | 每行带 `parent`、`children` |
| 记忆图谱 | `index/graph.py` `related` | 按共享代码、正文提及算相关模块 | 合并显式 `related`；排除直系 |
| 闸门 | `hooks/guard.py` `_guard_module`、`_pitfalls` | 目标模块没有记忆就放行；拦截消息列本模块的坑 | 计数和列坑都带上祖先 |
| 读码摘要 | `hooks/memories.py` 第 71 行 | 按“文字包含模块全名”判断提到了哪个模块 | 改为按完整名边界匹配，否则提到子模块会误算父模块 |
| 写入 | `service/record.py` | supersedes 只能填本模块；相近记忆只在本模块找 | 允许直系之间替代；兄弟模块有相近教训时提示写到父模块 |
| 迁移 | `catalog/migrate.py` | rename 只改一个模块；会同步改写 `parent` 字段 | rename 连带后代；`parent` 字段转为改名建议 |
| 同步 | `catalog/sync.py` | 只给未被覆盖的目录提议新模块；短名按 `split(".", 1)[1]` 比较 | 父模块目录里热度高的子目录提议为子模块 |
| 健康检查 | `metrics/health.py` `_duplicate_modules` | 短名相同（跨大类也算）或名字相近就报重复 | 比较完整名；直系不报；新增层级相关检查 |
| doctor | `cli/doctor_cmd.py` | 路径匹配不到文件的模块报空壳 | 有子模块的父模块不报空壳 |
| Wiki | `generate/wiki.py` `_page`、索引分组 | 只有合法模块名能当文件名；按大类分组 | 校验放开；索引按层级缩进 |
| 文档与模板 | `generate/templates.py`、`server/app.py` 工具说明、规则、技能、指南 | 一律写 `category.Module` | 说明多段写法和划分阶梯 |

### 2.4 新旧版本混用

团队里有人先升级时，旧版 pmem 读到新的 `modules.yaml`：

- 已登记的多段模块**能正常加载和使用**：`from_dict` 不校验名字格式，`resolve_module` 按全名命中；只是当作平级模块，没有继承、父子展示；
- 旧版不能**写入未登记的**多段模块（名字校验失败被拒）；
- 旧版 Wiki 不为多段模块生成页面（显示为代码文本而不是链接）；
- 旧版健康检查可能把父子模块报成疑似重复。

结论：混用时功能降级但不出错，不需要升 `schema_version`。doctor 检测到多段模块时提示“团队成员需升级到支持多段模块的版本”。

## 3. 设计

### 3.1 命名规则

- 格式：`大类.段1[.段2[.段3]]`，总共 2～4 段。大类小写，其余每段 PascalCase，规则同现在的模块名。
- 父模块 = 去掉最后一段；祖先 = 逐段去掉直到剩两段。`system.Ads.AdMob.Mediation` 的祖先依次是 `system.Ads.AdMob`、`system.Ads`。
- 子模块的大类必然与父模块相同。
- 写成 5 段或以上：直接拒绝，提示“渠道、平台、变体用 entity、applies、variants 表达；确实需要更深就把某一层提升为独立模块”。
- 常量 `MAX_MODULE_DEPTH = 4` 定义在 `core/registry.py`，暂不做成配置。

### 3.2 父模块是否必须登记

- 登记多段模块时，父模块必须已登记（可以没有自己的路径，只作为分组）；否则加载时不报错，但 doctor 和健康检查提示“缺少父模块 X”。
- 写入未登记的多段模块：父模块已登记才允许（自动成为未登记子模块，和现在的未登记模块一样由健康检查跟进）；父模块也没登记时拒绝，避免 Agent 随手造出一整棵树。

### 3.3 短名与别名

- `Module.name` 改为最后一段；另加 `Module.parent_id`、`Module.depth`、`Module.ancestors`。
- 短名索引登记最后一段，以及不带大类的相对名（`Ads.AdMob`）。在多个分支出现的短名（如两个 SDK 下都有 `Android`）解析时报歧义，并列出完整名。
- 别名规则不变：不带点的是短别名，带点的是完整别名。
- 原有的 `parent` 字段不再生效：加载时忽略；健康检查列出仍写着 `parent` 的模块，并给出 `pmem migrate rename <模块> <父模块>.<名字>` 的建议命令。本仓库目前没有用到这个字段。

### 3.4 检索继承

查某个模块（直接传 module，或由 path 定位到）时：

- **教训**：候选池 = 本模块 + 所有祖先模块的现行教训；
  - 祖先的得分按层级距离降权，每远一层乘 0.85；
  - 祖先在 `search.limit` 之外另给最多 `search.inherit_max` 条（默认 2，即最多 5 + 2 条）；本模块教训不足时，空出的名额也给祖先；
    实现调整：原设计是祖先占用 limit 里的名额，本模块教训会被挤掉 2 条，用户要求放宽为另算；没细分的模块不受影响；
  - 按议题（entity）过滤只作用于本模块，祖先不按议题过滤，只按相关度排序；
  - 祖先的条目带 `module` 字段和 `inherited: true`，并给一次说明提示：“来自上级模块，同样适用于本模块”。
- **功能记录**：只取本模块的（功能记录写的是本模块必须保持的行为，不继承）。
- **查父模块时**：不给子模块记忆的全文，响应里增加 `children`：每个子模块的名字、现行记忆条数、下级个数，
  以及它（含更下级）最新 5 条记忆的标题（教训和功能记录都算，来自更下级的带 `module`），细节再查子模块。
  实现调整：原设计只给条数；问“广告整体情况”时只看条数判断不了该查哪个 SDK，改为附最新标题。
- 全局检索（不带模块）不变；`as_of` 回看历史时同样继承，按当天有效的记忆计算。
- `scope: project` 的全项目级坑不受影响，照旧附加。

### 3.5 闸门与读码摘要

- 改子模块的文件：要求查过这个子模块（查子模块已经带上祖先教训）；只查过父模块不算。
- “模块有记忆才拦截”的计数改为本模块 + 祖先的现行记忆：子模块自己还没有记忆、父模块有时，照样拦截。
- 拦截消息和读码摘要里列出的已知坑，带上祖先的排除项、风险、更正（同样限额）。
- 修正读码摘要按文字判断提到模块时的子串误匹配（第 2.3 节第 7 行），改为按完整模块名的边界匹配。

### 3.6 写入

- **supersedes 放宽到直系**：可以替代本模块、祖先或后代模块的记忆；兄弟模块和不相关模块仍然拒绝，提示照旧。
  典型场景：写在子模块的教训后来发现适用于所有 SDK，在父模块写一条新的并替代子模块那条。
  实现调整：只允许替代本模块和后代模块的记忆，不允许替代祖先的。被替代的记忆会从它自己模块的检索里消失，
  子模块替代父模块的教训会让其他兄弟模块也看不到那条结论。
- **提升提示**：写教训时，如果兄弟模块有同一议题（entity）的现行教训（返回 `sibling_similar`；只按议题相同判断，不按相关度猜），提示“兄弟模块 X 有相近结论，若对所有子模块都成立，写到父模块 Y 并替代它们”。只提示，不拦截。
- 写入规则文字增加一句：“结论写在它适用的最高一层模块”。

### 3.7 显式关联 `related`

`modules.yaml` 的模块可以写：

```yaml
system.Ads:
  paths: [Framework/Ads/**]
  related:
    - module: infra.Build
      reason: iOS 与 Android 打入包体的广告 SDK 不同，改打包配置要同时看广告记忆
```

- 也接受简写 `related: [infra.Build]`。
- 检索和记忆图谱的 `related` 先列显式登记的（标“手工登记”），再列按共享代码、正文提及算出的；直系祖先和后代不出现在 `related` 里。
- 指向不存在的模块时，健康检查提示；`migrate rename` 时同步改写。

### 3.8 迁移

- `migrate rename A B`：A 的所有后代一起改名（前缀替换），每个旧完整名登记为对应新模块的别名，记忆文件一起搬；预览里列出连带改名的后代。B 的深度加上后代层数超过 4 段时拒绝。
- `migrate split A --to A.Child=路径`：父模块拆出子模块，现有拆分逻辑放开名字校验后直接可用，这是新建子模块的主要入口。
- `migrate merge A.Child A`：子模块并回父模块，用于处理空壳子模块；默认登记别名。
- `migrate move`、`deprecate` 不变。废弃父模块时提示它的子模块是否一起废弃（不自动连带）。

### 3.9 同步（`pmem sync`）

在现有“未覆盖目录”的提议之外，增加子模块提议（只预览，`--apply` 才写）：

- 某个已登记模块用 `**` 覆盖的目录下，有直接子目录满足：文件数 ≥ 30 或近 180 天热度 ≥ 5，且这个模块的文件数不少于 60（太小的模块不拆）；
- 提议名为 `<模块>.<子目录名 PascalCase>`，深度不超过 4 段；
- 已经被更具体的模块覆盖的子目录跳过。

### 3.10 健康检查与 doctor

- 疑似重复：比较完整名；直系模块之间不报；不同分支的同名末段（`...AdMob.Android` 与 `...Max.Android`）不报。
- 新增：
  - 缺少父模块的多段模块；
  - 名字超过 4 段的模块（手工改 yaml 绕过了校验）；
  - 只有一个子模块、自己又没有记忆的父模块（建议合并层级）；
  - 兄弟模块里反复出现的相近教训（建议提升到父模块）；
  - 仍写着 `parent` 字段的模块；`related` 指向不存在的模块。
- doctor：有子模块的父模块不报空壳；检测到多段模块时提示团队成员需升级。

### 3.11 展示

- `list_modules`：每行增加 `parent`、`children`。
- Wiki：索引页按层级缩进；子模块页顶部链接父模块，父模块页列出子模块。
- 记忆图谱：模块概览增加 `lineage`（祖先链）和 `children`。

### 3.12 文档、模板与技能

- MCP 工具说明（`server/app.py`）里的模块格式改为“category.Module，子模块用点号续写，最多 4 段”。
- 规则模板：加入“结论写在适用的最高一层”。
- pmem-bootstrap 技能加入划分阶梯：议题 → 小组件或变体 → 子模块 → 独立模块，各级门槛同 3.9；平台、渠道不做层级。
- pmem-consolidate 技能：处理“兄弟模块相近教训”“单子模块的父模块”。
- 指南 `docs/pmem-guide.html` 增加父子模块一节，以广告为例。

## 5. 分阶段实施

1. **命名与兼容**：registry 的命名、短名、祖先、深度校验；Wiki 校验放开；`parent` 字段忽略；读码摘要的子串匹配修正。完成后多段模块可以登记、写入、检索（暂不继承）。
2. **检索继承与闸门**：3.4、3.5；直系替代与提升提示（3.6）。
3. **维护工具**：迁移改名连带（3.8）、健康检查与 doctor（3.10）、同步提议（3.9）、`related`（3.7）。
4. **展示与文档**：list_modules、Wiki、图谱（3.11），模板、技能、指南（3.12）。

每个阶段：先写测试，全量 pytest 通过，再在临时项目里用广告场景（`system.Ads` + 4 个 SDK 子模块 + `infra.Build` 关联）实际跑一遍。

## 6. 风险

- **祖先教训的名额**：默认 2 条可能不够或太多，需要在真实项目上观察；`search.inherit_max` 做成配置，便于调整。
- **继承带来噪声**：父模块里与当前子模块无关的教训也会被带上；靠降权和限额控制，必要时再改成“祖先只取相关度命中的”。
- **结论写得太深**：提升提示只是提示，Agent 仍可能写到子模块；靠健康检查的“兄弟相近教训”兜底。
- **改名连带范围大**：父模块改名会搬动所有后代的记忆文件，预览里必须完整列出。
- **混用旧版本**：降级但不出错（2.4），需要在发布说明里写明升级建议。

## 7. 待确认

3. 子模块自己没有记忆、父模块有时，闸门照样拦截，是否合适？
