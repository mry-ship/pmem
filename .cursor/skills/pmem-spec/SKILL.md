# 模块规格

规格在 `.memory/specs/<模块>/`，一个模块一个目录，和 Wiki 分开。目录里四份分开：`策划设计.md`、`美术设计.md`、`程序设计.md`、`模块现状.md`。上下级和代码路径只在这个目录的 `index.md`。单给别人时只拷需要的那一份，例如只把 `美术设计.md` 给美术。Wiki 只浏览记忆。这里写模块现在是什么样。

## 先看缺谁

运行 `pmem spec`。无文件或首稿未完成的，用 `pmem spec init` 补骨架后再写。用户要一次补全时，运行 `pmem spec fill`：它只铺骨架并列出还没写完的模块，正文仍按下面的首稿写。废弃模块不要求补。

## 首稿

一次一个模块。读它的代码路径和资源，写四节：

- 程序设计：结构、数据、接口、依赖、状态、关键流程。写完去掉 `<!-- spec:empty -->`。
- 模块现状：按这份文字就能在另一个工程里把模块做出来的当前细节。写完去掉 `<!-- spec:empty -->`。
- 策划设计：只写代码或资源里看得到的数值、边界、表现、规则。看不到的完整策划保留 `<!-- spec:design-gap -->`，不要编。
- 美术设计：有画面时写风格、布局、各状态的画面、动效、资源规格。看不到的完整美术说明保留 `<!-- spec:design-gap -->`，不要编。没有画面就整节写成「本模块无画面」，不留空标记。这一节不用 `<!-- spec:empty -->`，缺了它也不算首稿未完成。

写之前用 `search_memory` 读该模块的功能记录，必须保持的行为写进现状。正文是规格，不要把记忆贴成清单。父模块不写子模块的正文，子模块单独一份。正文自己能读懂，不写「请打开某文件」。

四节都写模块现在的设计。不写「这一轮只新增」「本轮不重写」这类过程说明。还没写入的部分留 `<!-- spec:design-gap -->`，并写「尚未写入」。

四份正文按句换行，一句一行，句号或分号留在行尾。换一件事再空一行。不要把一整段写在同一行。

## 当轮更新

这一轮改了哪个模块，就只更新那一份，同一轮多次改动合并成一次。程序和现状只改正波及的段落，已有策划和美术保留。这轮新定的策划写入策划设计，新定的美术写入美术设计。不要整篇重写，不要改其他模块。

目录里还没有 `美术设计.md` 时补上这一份。没有画面就写「本模块无画面」。已有的这一份只改正波及的段落。

新模块如果整段是这轮用 AI 做的，策划和已经定下的美术按这轮对话写全，不留 `spec:design-gap`，除非还有没定的部分。没有画面就写「本模块无画面」。

## 手动补全

用户说「补全模块规格」，或运行了 `pmem spec fill` 时，先跑这条命令。它对列出的每个未完成模块，按首稿把四份写全。代码和资源里看得到的都写上。看不到的策划、美术写「尚未写入」，并保留 `spec:design-gap`。没有画面就写「本模块无画面」。已经写过且没有空标记的段落不要整篇重写。一句一行。

## 写完

`updated` 改成今天。然后 `pmem spec index` 刷新目录。文首事实由命令维护，不要手改那一段。目录的留空列标出策划或美术仍留空，以及旧稿缺了这两节；这不改变首稿是否完成。
