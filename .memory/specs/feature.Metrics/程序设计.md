## 程序设计

`metrics/events.py` 把本机事件追加到用户缓存目录的 `events.jsonl`。
超过 20 MiB 改名为 `events.old.jsonl`；Windows 上改名失败就跳过本次轮转，照常追加。
环境变量 `PMEM_NO_EVENTS` 存在则不写。
坏行和不是对象的 JSON 跳过。

`metrics/cite.py` 用字面指纹判断回复有没有采用记忆。
中文连续至少 4 字切 4 字片段；标识符至少 4 个字符。
重合比例达到 0.15 算采用。
只读 transcript 里助手的纯文本。
结果缓存在 `cites.json`。

`metrics/report.py` 做收益报告。
新写记忆按记忆文件统计：作者是本机用户、ULID 时间在统计期内；不靠事件日志，避免关掉事件后漏数。
终端检索按前后 30 秒挂到最近的对话。
防错类占比只在教训里算，功能记录和规划不进分母。
功能记录覆盖看 stop 事件的 `required` 模块，同一对话（或首尾各放宽 60 秒）有没有同模块功能记录；旧日志没有 `required` 的不计。
对话内重复按压缩切分，压缩后合理重发全文不算重复。

`metrics/health.py` 做健康报告，默认 60 天，只渲染有问题的节。
记忆文件重复由迁移抛错时作为一节列出，不让整份报告异常。
被拒写入按 `REJECT_CODES` 归类。
看门狗重启只计崩溃和超时，不含代码重载。
本机检索少于 20 次时不列没检索过的模块，也不用「没用过」作为归档依据。

`metrics/cleanup.py` 给出严格的清理候选，只建议归档、从不删除。
`metrics/audit.py` 给出未登记模块的转正提示和召回偏低。
`metrics/memmap.py` 在图数据上加漏记、断链、悬而未决、过期。
漏记看近 30 天提交，一次改动超过 100 个文件的大批提交不算。

`generate/memmap.py` 画出单文件 HTML；数据内嵌，不联网。
`cli/map_cmd.py` 默认写到 Wiki 目录下的 `map.html`；`--json` 只打印数据。
图数据本身由检索模块的 `index/memmap.py` 从记忆文件推出。

`bench/runner.py` 在独立 git worktree 里跑对照。
on 组复制当前 `.memory` 并内联 MCP；off 组清空条目且不给 MCP。
两组都不加载项目或用户设置，因此不触发 Hooks。
Agent 结束后才放入隐藏验收文件。
单次普通异常记失败并继续；缺 SDK 或没设 `CURSOR_API_KEY` 才整场中止。
验收命令超时 600 秒记为失败而不是崩溃。
汇总在 `finally` 里写，中途中止也留下 `summary.md`。

所有权：图数据由 Retrieval 的 memmap 从记忆文件推出；Wiki 目录校验与 Wiki 模块共用；compact 门槛与 Curation 相同。
本模块拥有事件日志、收益口径、健康节选、清理候选、对照实验和 map 的 HTML 画面。

事件类型闭集：search、mcp_search、search_call、search_call_unseen、record、mcp_record、record_call、record_rejected、gate、prompt、edit、stop、digest、compact、server_restart。
被拒写入中文名：字数不在允许范围、疑似敏感信息、当天同议题条数达到上限、草稿覆盖不被允许、模块已废弃（只读）、大类不存在、模块名有误、modules.yaml 有误、缺少议题、类型不对、状态不对、适用范围不对、替代关系成环、替代了别的模块的记忆、议题名不对（多行或过长）；对不上的归「其他」。

入口：`pmem report`、`pmem health`、`pmem map`、`pmem bench`。

数据形状与闭集词表：
事件类型闭集见上文。
被拒写入中文名见上文。

决定表：
事件文件超过 20 MiB 改名为 events.old.jsonl。
中文引用切 4 字片段；标识符至少 4 个字符；重合比例达到 0.15 算采用。
终端检索按前后 30 秒挂到最近的对话。
功能记录覆盖首尾各放宽 60 秒。
health 默认 60 天。
本机检索少于 20 次时不列没检索过的模块。
漏记看近 30 天提交；一次改动超过 100 个文件的大批提交不算。
防错类占比目标不低于 30%；功能记录覆盖目标不低于 80%。
验收命令超时 600 秒。

关键流程：
report、health 始终返回 0。
map 默认写 HTML；`--json` 只打印数据。
bench 在独立 worktree 里跑 on/off；缺 SDK 或 Key 整场中止。

入参字段闭集：
`pmem report`：`--days` 缺省 30；`--json` 缺省假；始终返回 0。
`pmem health`：`--days` 缺省 60；`--json` 缺省假；始终返回 0。
`pmem map`：`--out` 可省略，缺省为 wiki.dir 下的 map.html；`--days` 缺省 30 只改漏记窗口；`--json` 为真则不写文件。
`pmem bench`：位置参数 cases 可省略，缺省 bench/cases.yaml；`--arms` 缺省 on,off，只能含 on 或 off；`--repeats` 可省略；`--model` 可省略；`--only` 可重复；`--out` 缺省 bench-results；`--dry-run` 缺省假。

原文（须按字面抄）：
事件文件名 events.jsonl，轮转后 events.old.jsonl。
环境变量 PMEM_NO_EVENTS 存在则不写事件。
引用缓存 cites.json。
对照实验汇总文件 summary.md。
MCP 子进程带 PMEM_NO_EVENTS=1。

出参字段闭集：
report、health 始终返回 0；可 `--json`。
map 默认写 HTML；`--json` 只打印数据。
wiki.dir 在项目外且未传 `--out` 返回 2。
bench：缺 SDK 或 Key、用例不存在、`--arms` 非法返回 2；dry-run 不合格返回 1；正常跑完 0。

失败条件：
wiki.dir 在项目外且未传 `--out`：map 退出码 2。
bench 缺 SDK 或 Key、用例不存在、`--arms` 非法：退出码 2。
bench `--dry-run` 不合格：退出码 1。
PMEM_NO_EVENTS 存在：不写事件，不算失败。
report、health：始终退出码 0。

配置与环境变量：
PMEM_NO_EVENTS：存在则不写事件；MCP 子进程强制带 PMEM_NO_EVENTS=1。
CURSOR_API_KEY：bench 缺此键或 SDK 时整场中止，退出码 2。
wiki.dir：map 默认输出目录。
本模块不读其它配置键。

生成物：
本机 `events.jsonl`，超过 20 MiB 改名为 `events.old.jsonl`。
引用缓存 `cites.json`。
map 默认 `{wiki.dir}/map.html`。
bench 结果目录含 `results.jsonl` 与 `summary.md`。
