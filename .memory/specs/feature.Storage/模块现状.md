## 模块现状

本模块没有独立命令。
写入、确认、归档、迁移、过期核对和闸门快照都走这里。

必须保持：查不出草稿是否已提交时拒绝覆盖。
git 或 svn 缺失、超时不抛异常，返回码 127。
读失败码是 `storage_read`，写失败是 `storage_write`，草稿拒绝是 `draft_forbidden`；调用方逐条报告，不抛栈。
改动时刻精确到秒，不要退回按天的接口。
路径必须分批，不能一次塞爆命令行后当成都没改过。
Git 提供写入版本之后合入的提交；SVN 和无版本库返回空。
原子写失败要删临时文件。
空的 Git 仓库（还没有提交）算未提交，允许覆盖。
已提交后又在工作区改过，仍算已提交，不能当草稿覆盖。

一轮例子：Git 仓库里一条记忆已经 `git add` 并提交。
同一作者带 draft_id 再写，返回 draft_forbidden，文件内容不变。
把该文件改成未跟踪的新 id 文件则允许覆盖。

测试在 `tests/storage/`、`tests/vcs/`。
本机没有 svn 时部分用例会跳过。

单独拿走时还要带走的依赖规格：
infra.Model（条目形态、ULID、svn_auto_add）。
