Claude 侧已按解析后的绝对路径启用，不再按目录名误伤同名项目。另外两处还没收口。

Cursor 的批准键仍是 project-{序号}-{文件夹名}-pmem。
_folder_indexes 用 root.name 收集序号，并且总会带上 0。
两个都叫 MyApp 的目录会共用同一条批准；
后跑的 pmem init 会删掉旧哈希再写上这次的配置哈希。
配置一样时等于给另一个同名项目也批了；
配置不一样时会把对方的批准冲掉。

Codex 新建信任段是 [projects.'{路径}']。
路径里有单引号（例如 C:\Users\O'Brien\proj）会把 ~/.codex/config.toml 整份写成非法 TOML。
现在用 write_atomic 整文件替换，写坏就是整份配置都解析不了，不是只坏一行。

Claude 匹配会对 ~/.claude.json 里每个绝对路径 key 调用 Path.resolve()。断网的 UNC 或掉线盘符不会马上抛错，可能把 pmem init 卡住很久。
