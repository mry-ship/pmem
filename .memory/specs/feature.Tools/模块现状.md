## 模块现状

MCP 工具只有五个：`search_memory`、`record_memory`、`confirm_memory`、`memory_graph`、`list_modules`。
归档、种子、合并、词频、断行、补锚点只走命令行。

必须保持：所有工具返回（含失败）都带 `"server": "pmem"`。
MCP 覆盖草稿时，空列表等于没传，不能用空列表清空替代关系或别名。
`record_memory` 不暴露状态字段；新建用配置默认状态，覆盖沿用草稿原状态。
检索 `limit` 为 0 或省略时用配置，再夹到 1 到 10。
未接入项目时提示先在项目根运行 `pmem init`。
根目录解析顺序：`--root`、`PMEM_ROOT`、`CLAUDE_PROJECT_DIR`、当前目录；含 `${` 的未展开变量跳过。
写入成功后若 `wiki.auto` 为真就重生 Wiki；失败只进警告，不影响写入。

命令行同一套服务：`search`、`record`、`confirm`、`graph`、`list` 成功 0、业务失败 1；项目外或配置错为 2。
命令行输出不加 `server` 标记。

一轮例子：record_memory 不传 supersedes（MCP 侧等于空列表）去覆盖一条带替代关系的草稿。
写入成功后 supersedes 仍是原列表，返回带 server 为 pmem。
命令行 `pmem record --draft-id <id> --supersedes` 不跟值则清空替代关系。

测试在 `tests/test_server.py`、`tests/test_service.py`、`tests/core/test_secrets.py`。
冒烟脚本是 `scripts/smoke_mcp.py`。

单独拿走时还要带走的依赖规格：
infra.Model（类型、状态、写入长短与每日上限）。
feature.Storage（落盘、草稿是否已提交）。
feature.Retrieval（打分、分层、强制刷新索引）。
feature.Wiki（wiki.auto 时重生）。
feature.Metrics（写入事件）。
feature.ModuleCatalog（模块名校验与错误码）。
infra.Watchdog（stdio 进程与超时）。
infra.Common（root 解析顺序）。
