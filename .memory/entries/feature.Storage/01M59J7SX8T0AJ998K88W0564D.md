更正：draft_id 能否覆盖原先按“工作区有没有未提交改动”（is_uncommitted）判断。
confirm、archive、pmem format 改写已提交的记忆后它又变成“未提交”，同一作者带 draft_id 就能原地替换正文，历史丢失（SIMILAR_HINT 容易引导 Agent 这样做）。
现在改为 VCS.is_committed：有提交记录就不能覆盖。Git 用 git log -1 -- <文件>；SVN 状态不是 unversioned/added；无版本库始终可覆盖。
另：按路径查改动（changed_after，Git 和 SVN）改为按总长度 8000 字符分批调用（vcs/base.py 的 path_batches）。
原来所有路径拼进一条命令，Windows 命令行约 32K 上限，约 600 条记忆就报 WinError 206，被吞掉后当作“都没改过”，Wiki 和健康报告里的过期核对整体静默失效（TileMatch 有 993 条）。
