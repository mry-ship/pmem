风险：每次工具调用都会额外启动 pmem hook 进程，有固定开销。
2026-10-16 在本仓库（Windows，已装语义模型）实测冷启动：post-tool（读代码附摘要）约 0.46 秒，pre-tool（改前拦截）约 0.39 秒，CLI 的 pmem search --path 约 0.75 秒。
本仓库的 .cursor/hooks.json 里还挂着 spike/cursor_hooks/record.py 录制脚本，几乎每个事件都多启动一个 python；
afterFileEdit 一共要跑 5 条命令，是开销最大的地方。
这些录制脚本只在本仓库用于实测 Cursor Hook 的行为，pmem init 生成的模板（src/pmem/generate/templates.py）里没有，不影响接入方。
影响范围：本仓库里频繁读写文件时，Agent 的每一步都会变慢。
处理办法：Hook 行为实测完成后，从 hooks.json 删掉 spike 录制项；
接入方觉得慢的话，可以把 gate.read_digest 关掉，少跑一次 post-tool。
