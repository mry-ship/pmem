更正（多了一个前提）：闸门自动补 draft_id 要求同模块、同议题、同一层（教训一层，feature/plan 一层），且草稿还没提交。
原先不分层，同议题先写教训、再写功能记录时，后者会覆盖前者（2026-10-20 实际丢过 3 条教训）。
仍成立：Cursor 3.9 对 MCP 调用会采用 preToolUse 返回的 updated_input，闸门补的参数确实送到记忆服务（spike 载荷里 23 次 search_memory 都已带上注入的 source_conversation）。
afterFileEdit 按“模块|相对路径”记下本对话改过的文件；record_memory 的 preToolUse 里 Agent 没填 anchors 就补上该模块最近改过的最多 5 个文件，自己填了不覆盖。
已带 draft_id（传入或注入的），或载荷被转码损坏时，都不补锚点。
search_memory 只在工具名含 pmem，或 module/path 能在 pmem 注册表里解析时才注入；
Cursor 的 tool_name 只有 "MCP:search_memory"，原先会注入别家同名工具。
不带模块的全局检索不注入，代价是收益报告里这类检索少了对话归属。
要把同一层、同议题拆成多条时，换议题名或用终端 pmem record。
