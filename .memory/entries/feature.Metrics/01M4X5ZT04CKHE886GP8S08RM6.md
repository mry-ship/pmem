收益统计的数据口径（Cursor 3.9 实测）：stop Hook 的 input_tokens / output_tokens / cache_read_tokens / cache_write_tokens 是单轮（每个 generation）的值，不是对话累计，按对话求和即可；
input_tokens 已包含 cache_read_tokens。
stop payload 还带 user_email，事件日志不记录它。

事件日志 events.jsonl 只在用户缓存目录（不进仓库），PMEM_NO_EVENTS=1 可关闭。
MCP 检索在服务端记 search 事件，对话 id 依赖 Hook 注入 source_conversation（MCP 场景是否生效尚未验证），因此 Hook 侧另记 mcp_search（从 afterMCPExecution 结果里正则取 id）作为兜底；
Agent 在终端里跑 pmem search 时检索事件没有对话 id，report 按 30 秒内紧邻的 search_call(via=cli) 关联。

“对话对照”只是观察数据：用到记忆的对话与没用到的任务难度不同，每组少于 5 个对话时报告会注明样本不足，严格对比用 pmem bench。
