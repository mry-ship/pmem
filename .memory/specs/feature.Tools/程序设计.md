## 程序设计

`service/` 按职责拆成基类和四组操作：检索、写入、状态、整理。
`MemoryService` 由它们多重继承组成，对外导入路径不变。

`server/app.py` 的五个 MCP 工具都经 `call()` 执行。
一把锁串行，避免索引和 sqlite 被线程池并发踩踏。
返回一律带 `"server": "pmem"`，包括未接入项目和内部错误；闸门靠它认是不是本服务。
JSON 用 UTF-8、不转义非 ASCII。
每次调用前看 `config.yaml` 的修改时间和大小，变了就关掉旧服务再重建；写入规则和检索设置下一次调用生效。
`server.watchdog` 和 `server.request_timeout` 由看门狗在启动时读取，改了仍要在 Cursor 里重启。
配置写错时返回原因，改好即恢复，不让工作进程启动即崩。

`service/record.py` 在校验前和写入后各强制刷新一次索引。
空列表在 MCP 里当作没传，覆盖草稿时沿用原值；命令行只写参数名不跟值才表示清空。
跨模块替代只允许本模块或其下级。
覆盖时替代链走回自身则拒绝，避免环。
密钥扫描覆盖正文、议题、别名、锚点、摘要、验证和适用条件。
每日上限对「同模块同议题当天的草稿覆盖」和「替代仍现行记忆」豁免。
未填锚点时从被替代者继承，最多 10 个。
绝对路径转成相对路径，并按磁盘真实大小写拼；调用方显式传入且文件不存在或在项目外时才警告。

`service/search.py` 把检索参数交给索引，再补对话内去重和字段说明。
字段说明类提示每个对话给一次；`seen_hint` 每次都给。
按 id 取全文时不折叠。
查父模块时附各下级最新 5 条标题，含功能记录。
相关模块最多 3 个，直系不算。

`service/status.py` 提供确认、归档、恢复、种子转正和撤销合并。
这些不暴露为 MCP 工具。
`core/secrets.py` 内置私钥、AWS、GitHub、Slack、JWT、密钥赋值和中文「密码：」规则；项目可追加正则。

所有权：打分与分层在 Retrieval；落盘在 Storage；Wiki 重生在 Wiki；事件在 Metrics；看门狗进程在 Watchdog。
本模块拥有五件工具的参数契约、写入拒绝码、覆盖草稿语义和来源标记。

写入拒绝码闭集：content_length、secret、kind_invalid、status_invalid、scope_invalid、entity_missing、entity_invalid、module_deprecated、daily_cap、draft_forbidden、supersede_cycle、supersede_cross_module，外加目录模块的 category_unknown、module_invalid、modules_yaml 和存储码。

入参字段闭集：
search_memory：module、path、entity、query 皆字符串缺省空；limit 整数缺省 0 表示用配置再夹到 1 到 10；as_of 字符串缺省空；full 布尔缺省假；ids 字符串列表可空；source_conversation 由系统填，调用方不必传。
record_memory 必填：module、entity、kind、content。
record_memory 可选：supersedes、anchors、aliases 为字符串列表；summary、verify、applies、scope、draft_id、source_conversation 为字符串缺省空。
MCP 侧空列表等于没传；命令行只写参数名不跟值才表示清空。
confirm_memory 必填 ids 字符串列表；可选 source_conversation。
memory_graph 必填 module；可选 entity 缺省空。
list_modules 可选 category 缺省空。
命令行同名入口：search、record、confirm、graph、list。
命令行专有、不暴露为 MCP：archive。
record 的 `--seed` 是标志，不是独立子命令；`pmem seed` 在 Curation。

入口：五个 MCP 工具 search_memory、record_memory、confirm_memory、memory_graph、list_modules，以及命令行同名入口和 archive。

数据形状与闭集词表：
写入拒绝码闭集见上文。
MCP 空列表等于没传；命令行只写参数名不跟值才表示清空。

查父模块附各下级最新 5 条标题。

关键流程：

config.yaml 修改时间和大小变了则重建服务。

原文（须按字面抄）：
所有工具返回（含失败）都带键 server，值 pmem。
未接入项目时提示先在项目根运行 `pmem init`。
JSON 用 UTF-8、不转义非 ASCII。
命令行输出不加 server 标记。
similar 提示原文：similar 是同模块最相近的已有记忆：新结论与其中某条重复或推翻了它，就带 draft_id 重写并在 supersedes 填那条的 id；无关则忽略。
hints 结尾原文：以上只是提示，已写入；如需修改，带上 draft_id 再写一次即可覆盖。
anchors 提示原文：anchors 只写了文件：该文件以后任何改动都会让这条记忆标为“需核实”。
aliases 提示原文：没填 aliases：把现象和关键术语的其他常用叫法。

出参字段闭集：
成功共用：ok 为真，server 为 pmem。
失败共用：ok 为假，error 为人读文案，code 为稳定拒绝码，server 为 pmem。
search_memory 另有：module、items、features、module_exists、similar_modules、resolved_from、hint、inherited_hint、features_hint、applies_hint、verify_hint、seen_hint、related、children。
items 条字段：id、entity、kind、date、author、stale、summary、content、verify、applies、scope、module、check、verified、status、seen、inherited。
折叠后只留：module、id、entity、kind、date、stale、check、status、scope、applies、inherited，外加 summary。
record_memory 成功：id、module、entity、kind、path、overwritten、draft_id，可选 warnings、similar、sibling_similar、hints。
confirm_memory、memory_graph、list_modules 成功时 ok 为真；list_modules 含 categories、modules、registered_empty、project_root。
失败时省略成功字段；warnings、similar、sibling_similar、hints 无内容时省略。
MCP 空列表等于没传该字段；命令行只写参数名不跟值才表示清空，与没传不同。

失败条件：
content_length：正文短于 write.content_min 或长于 write.content_max。
secret：正文、议题、别名、锚点、摘要、验证或适用条件命中密钥规则。
kind_invalid、status_invalid、scope_invalid、entity_missing、entity_invalid：对应字段不在闭集或空。
module_deprecated：目标模块已废弃。
daily_cap：同模块同议题当日新写超过 write.max_per_day_per_entity；草稿覆盖和替代仍现行记忆豁免。
draft_forbidden：目标是未提交草稿且不允许覆盖。
supersede_cycle：覆盖后替代链走回自身。
supersede_cross_module：跨到非本模块且非下级。
未接入项目：ok 为假，提示先在项目根运行 `pmem init`，仍带 server=pmem。
配置写错：返回原因文案，不让工作进程启动即崩。

配置与环境变量：
write.content_min 缺省 20；write.content_max 缺省 5000；write.recommend_max 缺省 600；write.max_per_day_per_entity 缺省 5；write.secret_patterns 缺省空列表；write.default_status 缺省 active。
search.limit 缺省 5；search.max_per_batch 缺省 2。
wiki.auto 缺省真。
server.watchdog、server.request_timeout 由看门狗启动时读，本模块热重载不改它们。
本模块不读 PMEM_CACHE_DIR。

生成物：
本模块不直接写记忆文件；落盘由 Storage。
wiki.auto 为真时请 Wiki 重生页面。
