## 模块现状

用户可见入口是 `pmem <子命令>`。
已登记子命令：init、scan、sync、doctor、serve、hook、search、confirm、graph、terms、anchors、format、record、list、archive、seed、migrate、health、spec、wiki、map、compact、import、reindex、report、bench。
migrate 的子动作：rename、merge、split、deprecate、move、tidy。

退出码约定：成功 0；服务层业务失败 1；用法、环境、配置或模块目录错误 2。
hook 始终返回 0。

必须保持：没传和传了默认值要分清时，argparse 默认用空，真正默认在运行函数里取。
可跟多个值的参数用可重复加零个或多个值。
Windows 终端乱码时用 brief，不要把 JSON 经 PowerShell 管道按系统代码页解码。
新命令要同步改 README、使用手册、架构说明和总设计日常维护那一节命令表；文档目录被闸门忽略，漏改不会被拦。
模块规格从命令行就能调用：spec，可选 init、index、fill、complete 和 check。complete 是补全入口，fill 是旧名。

一轮例子：在项目根运行 `pmem search --module infra.Model --brief "配置"`，第一行是模块名和条数，其后每条以短横线开头，类型、议题、日期、id 用竖线分隔。

测试在 tests/test_cli.py、tests/test_layering.py。
分层测试与架构说明的允许导入表必须一致。

单独拿走时还要带走的依赖规格：
infra.Model（配置与项目根）。
feature.ModuleCatalog（预检要能加载模块名单）。
各子命令的业务规格按所有权分别带走，本模块不代替它们。
