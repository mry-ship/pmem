## 模块现状

入口：`pmem migrate <动作>`、`pmem sync [--apply] [--auto] [--history]`。
没有名单文件时返回 2，提示先按 pmem-bootstrap 划分模块。
无法迁移或无法同步返回 1。
预览和成功返回 0。

sync apply、以及 auto 真正写入新模块时，给还没有规格的模块铺四份骨架，并提示对 Agent 说「补全模块规格」。
预览不写规格。

必须保持：短名歧义要报错，不能默默选一个。
并入成环要报错。
路径写成单个字符串当一项，不按字符拆。
搬记忆文件走版本库的 move：SVN 已纳入的保留历史，未纳入的保持未纳入。
覆盖率分母不含第三方和忽略目录。
空壳模块（有路径、未并入、0 个文件、且没有下级）要能列出来。

一轮例子：名单里只有 gameplay.Jigsaw，路径 Assets/Game/Jigsaw/**。
sync 发现 Assets/Game/Shop 下 4 个脚本且近 180 天有改动，预览列出待登记 feature 或按项目类型推断的大类下的新模块；未加 apply 时名单不变。

测试在 tests/core/test_registry_*.py、tests/test_migrate.py、tests/test_migrate_split.py、tests/test_sync.py。

单独拿走时还要带走的依赖规格：
infra.Model（名单与配置形态）。
feature.Storage（搬记忆走版本库 move）。
feature.Spec（apply 真正写入新模块时补骨架）。
