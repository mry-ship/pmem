## 模块现状

入口：

- `pmem report`：`--days` 默认 30；始终返回 0。
- `pmem health`：`--days` 默认 60；始终返回 0。
- `pmem map`：默认 `{wiki.dir}/map.html`；`--days` 默认 30 只改漏记窗口；`--json` 不写文件。
- `wiki.dir` 指到项目外且未传 `--out` 时返回 2；`--out` 可以指到项目外。
- 首次建目录时写内容为 `*` 的 `.gitignore`。
- `pmem bench [cases.yaml]`：`--arms` 只能是 `on` 或 `off`，默认两组都跑；`--dry-run` 强制只跑 1 次、不调 Agent。
- 用例文件不存在、格式错、`--arms` 非法、缺 SDK 或 Key 返回 2。
- `--dry-run` 有用例没以 `dry_run` 结束、起始提交已通过、或一条都没跑时返回 1。
- 正常跑完返回 0，单个用例失败不中止。

必须保持：防错类占比只算教训，目标不低于 30%；功能记录覆盖目标不低于 80%。
清理建议归档须同时满足：关联代码全部不存在（没写锚点时看正文提到的文件和类，至少 2 处、找到不到 20%）、同议题没有其他现行记忆、没被引用、统计期内本机没用过。
排除项、风险、更正、全项目级、种子最多到待核对。
对照实验测的是记忆内容本身，不测 Hooks。
MCP 子进程带 `PMEM_NO_EVENTS=1`，不污染个人报告。

一轮例子：30 天内本机作者新写 2 条 exclusion，无功能记录。
`pmem report` 的防错类占比为 100%，功能记录覆盖在没有 required 字段的旧 stop 上不计。
`pmem health` 若检索次数少于 20，不出现「没检索过的模块」节。

测试在 `tests/metrics/`、`tests/bench/`、`tests/test_memmap.py`。
本仓库用例如 `bench/cases.yaml`。

单独拿走时还要带走的依赖规格：
infra.Model（本机缓存目录、类型闭集）。
feature.Retrieval（图数据 memmap、锚点过期）。
feature.Wiki（默认输出目录 wiki.dir）。
feature.Curation（compact 条数门槛）。
infra.Watchdog（重启事件种类崩溃、超时、重载；健康报告不计重载）。
feature.Tools（被拒写入码 REJECT_CODES）。
