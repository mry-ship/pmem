## 程序设计

`src/pmem/generate/spec.py` 做确定性的读写。
`project_spec_dir` 把配置路径解析到项目内，指到项目外就返回空。
`init_specs` 给还没有目录的模块建目录，并写入四份骨架：策划和美术带设计留空标记（spec:design-gap），程序和现状带空标记（spec:empty）。
已有的那一份直接跳过。
以前的单文件 `<模块>.md` 会按四个标题拆进目录，句子不改。
`index` 只重写各模块的 `index.md` 和总目录，不改四份正文，也不补还没有的那一份。
总目录多一列「留空」：策划或美术文件里还有设计留空标记，就标「策划」「美术」；
缺了那一份，就标「缺策划节」「缺美术节」；
都没有则是「无」。
这一列不改变完成状态。
子模块在总目录里缩进，前面加 `└`。

完成情况：废弃模块是「不要求补」。
没有目录是「无文件」。
程序或现状那一份整行仍是空标记（`<!-- spec:empty -->` 单独成行），或缺少这两份，是「首稿未完成」。
正文里用反引号提到该字面量（如本模块自述）不算留空。
否则是「已有规格」。
美术那一份缺了、或仍留空，不算未完成。
策划/美术的设计留空同理：只认整行的 `<!-- spec:design-gap -->`。
`--check` 只把「无文件」和「首稿未完成」当未完成。

`src/pmem/cli/spec_cmd.py` 的 `ensure_spec_skeletons` 给已登记模块补还没有的骨架。
没有未合并的模块时直接返回，不创建规格目录。
模块名单读不了时返回说明，不中断调用方。
`pmem init` 遇到这种情况仍完成接入，并在输出里写明规格骨架未写。
`run_spec` 读配置和模块目录。
`spec.dir` 无效时向标准错误打印并返回 2。
`init`、`fill`、`complete` 或 `index` 遇到不能落盘的模块名或符号链接页面，也返回 2。
`complete` 与 `fill` 同一条实现：在骨架之后刷新总目录，先打印「补全模块规格：本命令铺骨架并列出缺谁，正文由 Agent 按 pmem-spec 写到至少九成八。」
有未完成首稿时列出模块并返回 1，并说明按 pmem-spec 写满栏目再合上代码反推，直到能单独拿走、已实现的对外契约能从规格还原到至少九成八；
空标记都去掉时打印「规格首稿都已写完。」并提醒仍要合上代码反推，直到已实现的对外契约能从规格还原到至少九成八，返回 0。
没有已登记模块时只打印说明并返回 0，不说首稿都已写完。
不加子命令时只打印「模块名  状态」，有 `--check` 且仍有未完成时返回 1，否则返回 0。

`pmem init`、`pmem sync --apply`，以及 `pmem sync --auto` 实际追加了模块时，都会调用 `ensure_spec_skeletons`。
新写出骨架时，同步命令再提示对 Agent 说「补全模块规格」。
预览不同步规格。

命令在 `src/pmem/cli/main.py` 登记为 `spec`，可选参数是 `init`、`index`、`fill`、`complete` 和 `--check`。
`complete` 是补全模块规格的入口，与 `fill` 同一条实现；`fill` 是旧名。

骨架不放 `.gitignore`。

所有权：命令行只写骨架、模块索引里的事实和总目录。
四份正文由 pmem-spec 技能写。
技能的反推循环是写正文的标准，不在本模块的 Python 里执行。
命令行不能判断能不能拿走复用。
接入、同步只调用补骨架，不写正文。

骨架原文：策划以设计留空标记开头，下一句是「首扫未从代码中看到的完整策划，此处留空。」
美术骨架说明无画面写「本模块无画面」，有画面写风格、布局、状态、动效和资源规格。
程序在空标记后列出栏目：入口、入参字段闭集、出参字段闭集、数据形状与闭集词表、所有权、决定表、失败条件、配置与环境变量、关键流程、生成物、原文（须按字面抄）。
现状在空标记后列出栏目：必须保持、一轮例子、单独拿走时还要带走的依赖规格。
模块 index 的事实三段：上级、下级、代码路径，包在 facts 起止注释之间。

入口：`pmem spec [init|index|fill|complete] [--check] [--root]`。
`pmem init`、`pmem sync --apply` 和自动登记真正写入新模块时调用补骨架，不写正文。

数据形状与闭集词表：
action 闭集：init、index、fill、complete。
状态闭集：无文件、首稿未完成、已有规格、不要求补。
留空列闭集：无、策划、美术、缺策划节、缺美术节，可并列。

决定表：
本命令无超时、重试、容量。
完成状态只看程序和现状有没有空标记，不判断正文是否达到九成八。
废弃模块不计入 `--check`。

关键流程：
complete 与 fill 先补还没有的骨架，再列出空标记还在的模块。
有未完成返回 1；都去掉仍提醒反推到九成八，返回 0。
没有已登记模块不建目录，不说首稿都已写完。

入参字段闭集：
命令是 `pmem spec`。
位置参数 action 可选，闭集为 init、index、fill、complete；不加则只打印「模块名  状态」。
标志 `--check` 为真假，缺省假。
标志 `--root` 缺省当前目录。

原文（须按字面抄）：
空标记原文是 `<!-- spec:empty -->`。
设计留空标记原文是 `<!-- spec:design-gap -->`。
模块索引事实起止原文是 `<!-- spec:facts:start -->` 与 `<!-- spec:facts:end -->`。
四份正文文件名是 `策划设计.md`、`美术设计.md`、`程序设计.md`、`模块现状.md`，另加 `index.md`。
complete 与 fill 第一行：补全模块规格：本命令铺骨架并列出缺谁，正文由 Agent 按 pmem-spec 写到至少九成八。
未完成第二行：这些模块的四份正文还没写全：<模块顿号分隔>
未完成第三行：本命令只铺骨架、不写正文。按 pmem-spec 对上面每个模块：先按代码写满骨架栏目（含入参和出参字段闭集、失败条件、配置与环境变量、生成物、须按字面抄的原文、依赖规格），再合上代码反推，推不出的补进规格，直到能单独拿走、已实现的对外契约能从规格还原到至少九成八。
空标记都去掉：规格首稿都已写完。单独拿走做出相似或一样的实现，仍要按 pmem-spec 合上代码反推，直到已实现的对外契约能从规格还原到至少九成八。
init 成功：规格骨架：新写 <N>，已有 <M>，目录 <路径>
没有模块名单：还没有模块名单，规格等划分模块后再补
没有已登记模块：还没有已登记模块，规格目录等划分模块后再补
spec.dir 在项目外（complete/fill 铺骨架）：spec.dir 指向了项目目录以外，规格骨架未写
spec.dir 在项目外（pmem spec）：spec.dir 指向了项目目录以外，已拒绝
名单读不了（铺骨架）：模块名单读不了，规格骨架未写：<异常>
名单读不了（pmem spec）：模块名单读不了：<异常>
不能落盘：有 <N> 个模块不能写成规格文件：<最多 10 个、顿号分隔>
index 成功：规格目录已更新：<路径>

出参字段闭集：
列表模式标准输出每行「模块名  状态」，状态闭集：无文件、首稿未完成、已有规格、不要求补。
`--check` 有未完成返回 1，否则 0。
init 成功 0，spec.dir 在项目外或符号链接返回 2。
complete 与 fill 有空标记返回 1，都去掉返回 0。
index 成功打印「规格目录已更新：」加路径。
总目录表格列：模块、状态、更新、留空。
complete 与 fill 可选字段无：标准输出只有上述固定句，不带 JSON。

失败条件：
spec.dir 指到项目外：标准错误打印「spec.dir 指向了项目目录以外，已拒绝」，退出码 2；铺骨架时打印「spec.dir 指向了项目目录以外，规格骨架未写」，退出码 2。
模块名不能落成页面或目录是符号链接：退出码 2，文案「有 <N> 个模块不能写成规格文件：」。
complete 或 fill 时程序或现状仍有空标记：退出码 1，列出模块名。
`--check` 有无文件或首稿未完成：退出码 1。
没有已登记模块：退出码 0，不建规格目录，打印「还没有已登记模块，规格目录等划分模块后再补」。
命令行不判断反推是否够九成八；空标记去掉即 complete 返回 0。

配置与环境变量：
spec.dir：字符串，缺省 `.memory/specs`，必须解析到项目内。
spec.reminder：布尔，缺省假；本命令不读，闸门读。
本模块不读环境变量。

生成物：
`.memory/specs/<模块>/` 下五份：四份正文加 `index.md`。
总目录 `.memory/specs/index.md`，文件头生成标记由 index 命令维护。
本模块不写四份正文的内容。
