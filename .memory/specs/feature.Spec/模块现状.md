## 模块现状

入口是四条命令：

- `pmem spec`：列出每个未合并模块的状态。
- `pmem spec init`：缺哪一份才写哪一份骨架。输出「规格骨架：新写 N，已有 M，目录 …」。
- `pmem spec complete`：补全模块规格的入口。铺骨架并列出空标记还在的模块。有未完成时返回 1，并提示写满栏目再合上代码反推到九成八。空标记都去掉时仍提醒单独拿走前要反推到九成八。没有已登记模块时只说明还没到这一步，不说首稿都已写完。正文不由这条命令生成。`fill` 是旧名，行为相同。
- `pmem spec index`：刷新各模块 `index.md` 和总目录。留空列标出策划、美术仍留空，或还没有那一份。四份正文不被改写。
- `pmem spec --check`：有未完成首稿时返回 1。
- `pmem init`：模块已登记时顺手补骨架，下一步提示「补全模块规格」。
- `pmem sync --apply` 和自动登记真正写入后：只补还没有的骨架。

新骨架里，策划那一份写着「首扫未从代码中看到的完整策划，此处留空。
」美术那一份写着：无画面就写「本模块无画面」；
有画面时写风格、布局、状态、动效和资源规格，看不到的说明保留留空标记。
程序和现状各有一个空标记（spec:empty），后面是要填的栏目名。
上下级和代码路径在模块 `index.md`。
再次 init 时，已有正文保持原样。

符号链接的模块目录不覆盖，命令返回 2。
`spec.dir` 配成项目外（例如 `../outside-specs`）时不创建目录，返回 2。

一轮例子：已登记 gameplay.Jigsaw 且规格目录为空时，`pmem spec complete` 新建该模块目录和五份文件（四份正文加 index），标准输出第一行是「补全模块规格：本命令铺骨架并列出缺谁，正文由 Agent 按 pmem-spec 写到至少九成八。」并列出该模块为首稿未完成，退出码 1。
把程序和现状里的空标记删掉并写上正文后，再 complete 打印「规格首稿都已写完。」并提到合上代码反推到九成八，返回 0。
策划仍留空不影响退出码。

测试在 `tests/test_spec.py`。
必须保持：init 不覆盖已写正文；
index 只改模块索引和总目录；
美术那一份不带代码路径；
废弃模块不计入 `--check`；
没有已登记模块时不建规格目录，也不说首稿都已写完。

单独拿走时还要带走的依赖规格：
feature.ModuleCatalog（模块是否已登记、废弃与合并）。
feature.Onboarding（pmem init 调用补骨架、写出 pmem-spec 技能）。
infra.Model（spec.dir、spec.reminder 缺省）。
infra.Common（子命令登记与退出码）。
