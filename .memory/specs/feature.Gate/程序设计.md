## 程序设计

所有权：本模块拥有改代码前的拦截、读码附摘要、提问审查、结束提醒、终端写命令识别，以及规格是否已在本轮更新过。
不拥有 MCP 业务规则、模块目录解析、记忆落盘、配置缺省定义、Hook 模板生成。
配置键的缺省在 infra.Model。
改到没登记目录时与 Onboarding 扫描共用同一份代码扩展名和跳过目录，本模块不另定义。

入口：`pmem hook <事件> [--agent cursor|claude|codex]`，标准输入读 JSON，始终退出码 0。
内部事件闭集：session、prompt、pre-tool、before-mcp、after-mcp、edited、post-tool、compact、stop。
未知事件返回空对象。
无对话 id 时不建会话、不拦截。

Cursor 的 JSON：放行是 permission 为 allow；拦截是 deny，并带 user_message 与 agent_message，两段同一字符串；注入只回新增字段，避免把乱码写回整份参数；prompt 用 continue；stop 用 followup_message。
Claude 和 Codex：deny 走 hookSpecificOutput 的 permissionDecision；普通 allow 必须回空对象，不能回 allow，否则会替用户批准终端。
stop 续跑在 Claude 是 decision 为 block 加 reason。
标准输出 JSON 强制 ASCII。

模式闭集：off、warn、block，默认 block。
block 未查过就 deny；warn 每模块只 deny 一次；off 不拦。
空模块（本模块现行记忆 0 且上级教训 0）三种模式都不拦。
用户说了跳过标记等同不拦；已在 searched 里的模块不拦。

会话存在本机缓存 sessions 下。
数据形状与闭集词表：
会话字段闭集：searched、warned、edited、written、nudged、consult_nudged、skip、returned、recorded、cli_recorded、edited_files、consulted、analysis、reviewed、asked、review_nudged、skip_reason、skip_noticed、shell_before、late_warned、cli_pending、cli_record_pending、project_shown、project_done、stale_explained、spec_written、spec_nudged。
结束提醒分三本账：功能记录用 nudged，查阅和排查用 consult_nudged，规格用 spec_nudged。先催过查阅，同一对话里后来改了该模块，仍催功能记录。
【pmem】行按“；”分段；只解析【pmem修改】与旧写法【pmem】行（【pmem检索】【pmem查询】不算）。段内先去掉「标题」引号再匹配“无需记录”“无新结论”，避免记忆标题误触发。“无需记录”只放过同一段里点名的模块，且只放过功能记录和规格提醒。“无新结论”各段点名的模块取并集，只放过这些模块的查阅/排查提醒；任一段没点名则查阅/排查提醒全部不发（与段顺序无关）。无新结论不放过功能记录提醒；提问审查不受声明影响。
模式闭集：off、warn、block。
内部事件闭集见入口。

决定表：
会话文件名最长 80 字符。
TTL 7 天。
损坏 JSON 逐字段丢弃。
同一命令先查再写只认且、分号、换行；语句超过 40 句一律不算先查。
补锚点最多 5 个路径。
拦截列出坑最多 5 条。
通配展开最多 200 个目标。
晚到改动路径最多列出 5 个。
读码搜索摘要最多 2 个模块。

写入工具名（小写）闭集：write、strreplace、edit、multiedit、editnotebook、delete、search_replace。
只读摘要工具：read、grep、glob、semanticsearch、codebase_search。
认作本服务的工具：record_memory、search_memory、memory_graph。
Bash 和 PowerShell 归一成 Shell；apply_patch 归一成 Write。

终端命令算查过：命令名是 pmem，子命令精确为 search 或 graph，可出现在 uv、uvx、pipx、python、python3、py 之后。
写在或后面、或标准输出被丢弃（重定向到空、管道进 Out-Null 一类）不算。
输出里看不到模块名记 search_call_unseen，不算查过。
算写过：子命令 record，输出含模块名且含 draft_id。
同一命令内先查再写只认且、分号、换行；语句超过 40 句一律不算先查。

MCP 返回 ok 为真才登记。
search_memory 还要能认出是 pmem：返回带 server 为 pmem，或工具名含 pmem，或返回的 id 在本仓库。
record_memory 在 Agent 没填锚点、且没有草稿 id、且不是残缺解析时，补该模块本轮改过文件末尾最多 5 个路径；Agent 已填则不覆盖。
功能记录与教训的草稿分层，互不覆盖。
草稿已提交则不注入旧草稿 id。

stdin 按 UTF-8 替换错误并去 BOM；含非 ASCII 时同时试 GBK 回转，取乱码更少的一份。
都失败则只抠 ASCII 字段并标部分解析，此时不补锚点。
跳过标记在原文、回转和误解码形态都算。

规格文件落在 spec.dir 下、文件名是四份正文之一时记入 spec_written；index.md 不算。
这条路径仍在 ignore 里，不进入 edited，不因此再要求写功能记录。

关键流程：
有对话 id 才建会话。
改代码前按模式拦截未查过的模块。
读代码或搜索时代入摘要。
结束时按改动、查阅和规格是否已写追加 followup。
闸门内部出错自动放行，结束时通知一次。

入参字段闭集：
命令是 `pmem hook <event> [--agent cursor|claude|codex]`。
event 闭集：session、prompt、pre-tool、before-mcp、after-mcp、edited、post-tool、compact、stop。
agent 缺省 cursor，闭集 cursor、claude、codex。
标准输入是一份 JSON 对象。
闸门认、部分解析时按 ASCII 抠的顶层字段：conversation_id、generation_id、hook_event_name、tool_name、status、cwd、prompt、transcript_path、file_path、tool_input。
Claude 与 Codex 另认 session_id，normalize 后写入 conversation_id。
tool_input 里按 ASCII 抠的字段：file_path、command、cwd、module、path、entity、kind、query、target_directory、draft_id、target_file、target_notebook、file_paths。
另认列表键 target_directories、paths。
无 conversation_id（Claude 无 session_id）时不建会话、不拦截。
未知 event 返回空对象。
始终退出码 0。

原文（须按字面抄）：
Cursor 放行键 permission，值 allow。
Cursor 拦截 permission 为 deny，并带 user_message 与 agent_message，两段同一字符串。
Cursor 注入只回 updated_input，只含新增字段。
Cursor prompt 默认带 continue，值为真。
Cursor 给模型补上下文的键是 additional_context。
Cursor stop 续跑键是 followup_message。
Claude 与 Codex 拦截：hookSpecificOutput.hookEventName 为 PreToolUse，permissionDecision 为 deny，permissionDecisionReason 为文案。
Claude 与 Codex 普通放行必须回空对象，不能回 allow。
Claude 与 Codex 带 updated_input 时 permissionDecision 为 allow，键名 updatedInput。
Claude 与 Codex stop：decision 为 block，reason 为 followup 正文。
Claude 与 Codex 在 prompt 与 post-tool 补上下文：hookSpecificOutput.additionalContext。
发给 Agent 的自动文案以 `[pmem]` 开头。
warn 拦截后缀原文：然后重试本次修改。
block 拦截全文：pmem：<相对路径> 属于 <模块>（已有 <N> 条研发记忆）。请先调用 search_memory(module="<模块>") 了解已有结论，查过之后才能修改该模块。MCP 工具不可用时，在终端运行 pmem search --module <模块> 也算（输出不能丢弃，如 > $null、| Out-Null）；检索要真正返回结果才算查过。确实不需要记忆时，请用户回复“跳过记忆”。
上级有教训时，括号里在「已有 <N> 条研发记忆」后追加「，上级模块另有 <M> 条教训」。
warn 模式把「查过之后才能修改该模块。」起到跳过记忆整段换成「然后重试本次修改。」
结束未查全文：[pmem] <原因段>，这些模块已有研发记忆，但本轮回答前没有查过。请对每个模块调用 search_memory(module="<模块>", query="<问题要点>") 核对：与回答一致就简短说明“已核对记忆”；记忆里有排除项、风险或不同结论，请据此修正回答。
原因段闭集：你的问题涉及 <模块列表>；本轮看过 <模块列表> 的代码；两者都有时用中文逗号拼接。
结束改了没写全文：[pmem] 本轮修改了 <模块列表>，还没有写研发记忆。1) 每个模块用 record_memory 写一条功能记录（kind=feature）：需求来源（谁要求的、为什么）、必须保持的行为、适用条件（applies）、入口在哪；summary 写一句“什么行为必须保持”，不写“改了哪个方法”；已有功能记录说的就是这件事时用 supersedes 更新它，实现了某条规划（plan）也用 supersedes 替代它。2) 本轮另有以下内容时，再各写一条对应类型的教训（优先防错类，避免只记流水账）：试过不行、被排除的方向（exclusion，最值钱）；看代码看不出的约束或风险（risk）；推翻旧结论（correction）；确认的根因或踩到的坑（conclusion）；为什么选这个方案而不是别的（decision）。确实不需要记录（只改了注释、格式、重命名等，行为没变）时，在【pmem修改】行写“无需记录：<一句原因>”。不要询问用户。
结束排查没落结论全文：[pmem] 本轮是排查类对话，查了 <模块列表> 的记忆，却还没落结论。请为每个模块至少写一条教训（优先 exclusion：试过不行的方向；其次 risk / conclusion / correction）；确认没有任何可沉淀结论时，在【pmem修改】行写“已核对，无新结论”。不要询问用户。
结束只查没改全文：[pmem] 本轮查了 <模块列表> 的记忆，没有改代码也没有写记忆。得出了新结论就直接用 record_memory 记下（优先 exclusion / risk / conclusion / correction）；没有新结论时在【pmem修改】行写“已核对，无新结论”。不要询问用户。
结束规格没更新全文：[pmem] 本轮修改了 <模块列表>，对应的模块规格还没更新。请按 pmem-spec 更新 .memory/specs/<模块>/ 里对应的那一份：程序和现状只改正波及的段落，本轮新定的策划和美术写入并保留。无画面的模块美术节写「本模块无画面」。目录里还没有美术设计.md 时补上这一份。不要整篇重写，也不要改其他模块。不要询问用户。
无需记录原文：无需记录：
固定句：不要询问用户。
会话文件名：对话 id 只留字母数字下划线和减号，其余换成下划线，最长 80 字符。
闸门出错全文：[pmem] 记忆闸门刚才出错，那次已自动放行、没有做记忆检查（<最近一行错误，最多 200 字>）。请在回复里提醒用户运行 pmem doctor 查看原因（错误日志：<hook-errors.log 路径>）。
终端晚到改动全文：[pmem] 刚才的终端命令改了 <最多 5 个相对路径，顿号分隔>，属于 <模块>（已有 <N> 条研发记忆），但本对话还没查过该模块的记忆。请立即调用 search_memory(module="<模块>") 核对这次修改，与记忆冲突就改回。
检索失败仍写入全文：[pmem] 这条命令里对 <模块列表> 的检索没有成功（输出里看不到该模块），但命令随后已经改了它的文件。请现在用 search_memory(module="<第一个模块>") 补查，核对改动是否与已有记忆冲突。
读码摘要 intro 三种全文：
[pmem] <intro>，现行记忆 <N> 条，回答或修改前先看（只列标题，全文用 search_memory(module="<模块>", query=...)）：
含上级时在「条」后插入「（含上级模块的坑）」
[pmem] <intro>，该模块只有和这个文件无关的功能记录（要看用 search_memory(module="<模块>")）。改动前先看全项目通用的坑：
[pmem] <intro>，该模块还没有记忆。改动前先看全项目通用的坑：
intro 闭集：你正在看的 <相对路径> 属于 <模块>；你正在搜索的 <相对路径> 属于 <模块>
跳过通知全文：[pmem] 本对话已按“跳过记忆”关闭记忆检查（来自提问：“<跳过原因原文>”），<模块> 的记忆不会提示，改代码也不拦截。如果这不是用户的本意，请告诉用户：说 <恢复标记列表，每项用弯引号，顿号分隔；未配置则写（未配置）> 可以重新打开。
后台扫描出错全文：[pmem] 后台自动扫描新目录时出错：<错误>。请提醒用户运行 pmem sync 查看。
后台已登记全文：[pmem] 后台扫描发现新的代码目录，已自动登记到 .memory/modules.yaml，共<数量文案>：<最多 8 项分号分隔>。请在回复里告诉用户这次<数量文案>（写明数量），名字不合适可用 pmem migrate rename <旧名> <新名> 改，记得提交 .memory/modules.yaml。超过 8 项时列表后加「 等 <总项数> 项」。
后台待登记全文：[pmem] 后台扫描发现没登记的代码目录，待登记 <去掉「新增 」前缀的数量文案>：<最多 8 项>。请在回复里写明数量并提醒用户运行 pmem sync 预览、确认后 pmem sync --apply 登记。
skipped 为 comments 时，在「请在回复里」前插入「modules.yaml 正文里有注释，自动重写会丢失，所以没有自动登记；」

出参字段闭集：
始终退出码 0。
标准输出一份 JSON 对象，强制 ASCII。
Cursor 放行：permission=allow，可带 continue、additional_context、updated_input、followup_message。
Cursor 拦截：permission=deny，user_message 与 agent_message 同文。
未知事件：空对象。
Claude/Codex 见原文键名。
user_message 与 agent_message 同时出现且同文；followup_message 只在 stop 有待提醒时出现，否则省略该键。
additional_context 只在有注入时出现。
updated_input 只在补了 source_conversation 或草稿 id 时出现。

失败条件：
Hook 始终退出码 0。对外失败表现为 JSON deny 或 followup，不是非零退出。
block 且该模块有记忆或上级教训、且未查过、且未跳过：permission 为 deny。
warn 且该模块第一次未查过：permission 为 deny；同模块已 warned 则放行。
off、用户说了跳过标记、空模块（本模块现行 0 且上级教训 0）、已在 searched：不拦。
未知事件：空对象。
无对话 id：不建会话、不拦截。
闸门内部出错：自动放行；结束时 followup 出错通知，同一日志只通知一次。
中断、出错结束、跳过记忆、续跑回合（loop_count 或 stop_hook_active）：不追加结束提醒。

配置与环境变量：
gate.mode：字符串，闭集 off、warn、block，缺省 block。
gate.watch：路径列表，缺省空。
gate.ignore：路径列表，缺省见 Model。
gate.skip_markers、gate.resume_markers、gate.analysis_markers、gate.record_exempt：字符串列表，缺省见 Model。
gate.stop_reminder、gate.read_digest、gate.question_review：布尔，缺省真。
gate.analysis_reminder：布尔，缺省假（结束 followup 会打断用户阅读；需要时再开）。
spec.dir：字符串，缺省 `.memory/specs`。
spec.reminder：布尔，缺省假。
sync.auto：字符串，闭集 off、remind、apply；不为 off 时 stop 可带后台扫描通知。
会话与错误日志走 Config.cache_dir；环境变量 PMEM_CACHE_DIR 见 Model。

生成物：
本机缓存 `sessions/<对话id清洗>.json`，TTL 7 天。
不写项目内规格正文；只认 spec.dir 下四份正文文件名为已写规格。
