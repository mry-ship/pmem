## 模块现状

入口：

- `pmem compact`：`--min` 默认 5；`--module` 可过滤；`--entity` 必须同时给 `--module`，否则返回 2。
- `pmem compact --undo <合并后的 id>`：撤销一次合并，列出重新现行的原记忆和没恢复的原因；没有 `supersedes`、已经撤销过、或又被更新记忆替代时失败。
- `pmem anchors`：默认预览；`--apply` 写回；未知模块或 `--rename` 格式错返回 1。
- `pmem format`：默认预览「N 条有过长的行」；`--apply` 后同样文件再跑是 0 条。
- `pmem seed --plan`：`--top` 默认 10，只配合 `--plan`。
- `pmem seed --accept` 必须给 id、`--module` 或 `--all`；`--reject` 必须给 id；`--all` 只配合 `--accept`；给了 id 不能再给 `--module`。
- 非法组合返回 2，不执行另一个动作。
- `pmem record --seed` 写成 `status=seed`，立刻可检索；JSON 带 `status: seed`，`--brief` 和闸门摘要标「（种子，待确认）」。
- `pmem archive` / `pmem archive --restore`：有改动或全空成功为 0；只有 missing 或 skipped 为 1。
- `pmem terms`：`--top` 默认 300，`--min` 默认 2。
- `pmem confirm`：核对日期写成今天。

必须保持：功能记录和规划的写作提示只查需求来源与必须保持的行为，不再当变更记录查。
合并产物带 `supersedes` 后旧记忆从检索消失，文件保留；未填锚点时继承去重后最多 10 个。
`compact --undo` 之后可以用 `archive --restore` 重做合并。
被退回的种子恢复后仍是 seed。
已归档不能用 `draft_id` 覆盖。
归档合并产物不会让旧记忆重新出现。
`--rename` 同时改目录和其中某个文件时，文件规则写在前面。
一边带 `#` 另一边不带则报错。
目标文件不存在或找不到符号只警告，仍可 `--apply`。

一轮例子：同一模块同一议题已有 5 条现行记忆时，`pmem compact --module feature.Gate --entity Encoding` 打出 5 条正文和一条带全部 id 的 record 命令。
写入带 supersedes 后检索只剩新条；`pmem compact --undo <新id>` 后原 5 条重新可见，新条归档并带 reverted。

测试在 `tests/core/test_quality.py`、`tests/test_compact.py`、`tests/test_anchors_cmd.py`、`tests/test_lifecycle.py`、`tests/test_format_cmd.py`。

单独拿走时还要带走的依赖规格：
infra.Model（类型、断行、status=seed）。
feature.Tools（状态流转与合并统计的实现）。
feature.Onboarding（文件索引扫描）。
feature.Storage（写回与版本库）。
