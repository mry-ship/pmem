## 模块现状

入口：`pmem hook`；Cursor、Claude、Codex 的 Hook 配置由 Onboarding 写出。
Cursor 只有 sessionStart 经包装脚本；其余直接调 pmem。找不到 pmem 时包装脚本在 session 注入安装提示，其它 Hook 按 failClosed 为假静默放行。

发给 Agent 的自动文案都以 `[pmem]` 开头。
拦截时要求先 search_memory，MCP 不可用时终端 `pmem search --module` 也算，但输出不能丢弃；检索要真正返回结果。
warn 模式后缀是「然后重试本次修改。」
block 模式说明查过才能改，并提示用户可回复「跳过记忆」。
结束时未查、改了没写、只查没改、规格没更新，各有固定 followup，且写明不要询问用户。
规格提醒原文要求按 pmem-spec 更新对应那一份，程序和现状只改正波及的段落，新策划新美术写入并保留，无画面写「本模块无画面」，没有美术设计这一份时补上，不要整篇重写，也不要改其他模块。
spec.reminder 为假或闸门 off 时不发规格提醒。
同一模块一轮只提醒一次。
回复里写了「无需记录」且点名该模块，或只改了 record_exempt 文件，不提醒写功能记录，规格也不提醒。

必须保持：工具必须来自 pmem，别家同名 search_memory 即使 ok 也不算查过。
Windows 上传入的中文可能被转码，闸门要自动兼容，不能让中文路径或跳过标记失效。
Hook 出错自动放行并记日志，再提醒用户跑 doctor。
读代码附的是标题不是全文。
排除项、风险、更正在改前最多列 5 条，上级另加最多 2 条，全项目坑最多 3 条。
「需核实」脚注每个对话只解释一次。

一轮例子：对话改 `src/pmem/hooks/gate.py`，模块是 feature.Gate，本对话还没 search_memory。
pre-tool 返回 deny，agent_message 含模块名和 search_memory。
随后补查成功，同一文件再写则 allow。
失败例子：event 不是闭集内的名字时标准输出是空对象，退出码仍为 0。

测试在 tests/hooks/ 与 tests/test_hook_cmd.py。
规格相关用例：结束提醒一次、声明无需记录或免记录或 off 时不提醒、写规格文件本身不算业务改动。
夹具默认关闭 spec.reminder，专门用例再打开。

单独拿走时还要带走的依赖规格：
infra.Model（gate.mode、skip_markers、resume_markers、spec.reminder、record_exempt）。
feature.Onboarding（Hook 配置与包装脚本）。
feature.Tools（MCP 返回 server 为 pmem，工具名 search_memory、record_memory、memory_graph）。
feature.Spec（四份正文文件名，index.md 不算规格已写）。
feature.Retrieval（读码摘要只给标题）。
infra.Common（终端命令解析与对话交接）。
