# 模块规格

目的：每个已登记模块一份说明书。不拷源码。拿到另一个工程里，按这套文字能做出相似甚至一样的实现。

规格在 `.memory/specs/<模块>/`，和 Wiki 分开。目录里四份分开：`策划设计.md`、`美术设计.md`、`程序设计.md`、`模块现状.md`。上下级和本仓库代码路径只在这个目录的 `index.md`。给某一工种只拷那一份，例如只把 `美术设计.md` 给美术。要复用实现，拷整个模块目录（四份加 index）。所有权里点名依赖的其它模块，那些目录一并带走。index 里的路径只供原仓库定位；目标工程改成自己的路径，结构和契约保留。Wiki 只浏览记忆。

## 先看缺谁

运行 `pmem spec`。无文件或首稿未完成的，用 `pmem spec init` 补骨架后再写。用户要一次补全时，运行 `pmem spec complete`：它铺骨架并列出空标记还在的模块，正文仍按下面写到至少九成八。`pmem spec fill` 是同一条命令的旧名。废弃模块不要求补。`--check` 只看空标记，不等于已经能拿走复用。

## 一样和相似

一样：闭集词表、协议原文、入参和出参字段名、错误码、决定表里的数字、对外文案、生成物结构、配置键和环境变量，必须能从规格还原；换了就不是同一模块。
相似：流程、所有权、入口种类可以映射到新工程的命名和路径。
已实现的对外契约按规格能还原到至少九成八，这套规格才算有用。
九成八的分母是入参、出参、词表、数字、对外文案、生成物结构、失败条件、配置键和环境变量。
源码行数、内部函数名、测试夹具、代码里没有的策划，都不计入分母，也不要为凑九成八去编或去拷源码。
策划或美术仍留空的部分，不能声称那一部分一样，只能按已写入的做相似。

## 首稿

一次一个模块。读它的代码路径和资源，按骨架栏目写四节。没有的栏目写「本模块无此项」。这些小标题写完后仍要留在正文里，缺一个栏目就是缺口。

- 程序设计：入口、入参字段闭集、出参字段闭集、数据形状与闭集词表、所有权、决定表、失败条件、配置与环境变量、关键流程、生成物、须按字面抄的原文。写完去掉 `<!-- spec:empty -->`。
- 模块现状：必须保持的行为、一轮填全字段的例子、单独拿走时还要带走的依赖规格。写完去掉 `<!-- spec:empty -->`。
- 策划设计：代码或资源里看得到的数值、边界、表现、规则必须写全。写完后加一句「已实现行为的策划以代码可见规则为准」。独立于代码、扫代码也补不回来的完整策划稿才留 `<!-- spec:design-gap -->`，不要编，也不要把已写入的契约再标成策划留空。
- 美术设计：有画面时写风格、布局、各状态的画面、动效、资源规格。看不到的完整美术说明保留 `<!-- spec:design-gap -->`，不要编。没有画面就整节写成「本模块无画面」，不留空标记。这一节不用 `<!-- spec:empty -->`，缺了它也不算首稿未完成。

入口写清谁在何时进来（命令、协议、按钮、消息、定时），成功和失败怎么表现。
入参字段闭集：每个对外入口一张清单，字段名或标志名、含义、缺省、缺了或非法时怎样；只写「读一份 JSON」或「有若干参数」不够。
出参字段闭集：每个对外入口的返回或落盘字段名、含义、何时出现、何时省略；失败时的码和文案。只写「返回一份 JSON」不够。没传和传了空值要分开写。
失败条件：每种对外失败一张表，写触发条件、退出码或错误码、给用户或 Agent 的文案模板。只写「失败时返回非零」不够。本模块无对外失败就写「本模块无对外失败」。
配置与环境变量：本模块读取的每个配置键和环境变量，写键名、类型、缺省、非法或缺了时怎样。本模块无此项就写「本模块不读配置和环境变量」。
生成物：本模块写出的每个文件或页面，写路径模式、文件头标记、必含字段或短语。不要整份粘贴源码或模板正文。
闭集词表（类型名、状态名、事件名、错误码、原因词、对外工具名和命令标志）必须抄全，只写「有一张词表」不够。
所有权写本模块负责什么，明确不负责什么、由谁负责。跨模块只写契约，不抄对方正文。
决定表写阈值、公式、超时、重试、容量，公式里每个系数都有。
原文：其它程序会解析的键名、用户必须原样打出的标记、发给 Agent 或用户看的固定句、失败提示，必须按字面抄全。固定字按字面抄；会变的部分用尖括号写出，如 <模块>。整句写成「含某某」算缺口。只抄「关键句」或转述算缺口。
程序设计里出现的源码路径只供原仓库定位，不是目标工程必须同名；目标工程改路径，入口、词表、字段和数字保留。
一轮例子至少一组从输入到落盘或出画，字段填全。对外有失败码时再给一组失败。
依赖规格列出要一并带走的其它模块名；没有则写「无」。
必须保持写功能记录里的行为，以及测试锁住的对外表现。

写之前用 `search_memory` 读该模块的功能记录，必须保持的行为写进现状。正文是规格，不要把记忆贴成清单。父模块不写子模块的正文，子模块单独一份。正文自己能读懂，不写「请打开某文件」。不要写内部函数名清单，除非名字本身是对外契约。

四节都写模块现在的设计。不写「这一轮只新增」「本轮不重写」这类过程说明。还没写入的部分留 `<!-- spec:design-gap -->`，并写「尚未写入」。

四份正文按句换行，一句一行，句号或分号留在行尾。换一件事再空一行。不要把一整段写在同一行。

## 反推循环

写完必做，不是可选项。

1. 合上本模块的代码和资源，只留该目录四份加 index。
2. 只根据规格重做：入口怎么接、每个字段叫什么、数据怎么落、词表有哪些、失败怎么表现。
3. 凡是推不出来、只能含糊说「有个词表」、或把原文说成大意的，就是缺口。
4. 打开代码只为把缺口按字面抄进规格，不要趁机改写成摘要。
5. 再合上代码反推。

停手前，规格里必须能直接读到下面各项，并且已实现的对外契约能还原到至少九成八；缺一条就回去补，不要停：
- 入口小标题，以及每个入口的入参字段闭集和出参字段闭集；
- 出参可选字段写明何时出现、何时省略；没传与空值分开；
- 词表逐项列出，不是「有一张表」；
- 所有权：负责与不负责；
- 决定表：数字和公式，每个系数都有；
- 失败条件成表，或写「本模块无对外失败」；
- 配置与环境变量闭集，或写「本模块不读配置和环境变量」；
- 生成物：路径模式与标记，或写「本模块无生成文件」；
- 须按字面抄的原文已抄全：带尖括号占位的模板全文，没有只写大意、只抄关键句、或写成「含某某」；
- 一轮例子字段填全；有对外失败码时含失败；
- 依赖规格列出模块名，或写「无」；
- 策划已写入代码可见的规则，并写明已实现行为以这些规则为准。

空标记去掉、`--check` 通过，都不算停。
只写结构摘要或「这一轮改了什么」，反推会失败。
index 里的路径不能替代契约。

## 当轮更新

模块后来改了行为时用这一节：只更新那一份，同一轮多次改动合并成一次。程序和现状只改正波及的段落，已有策划和美术保留。这轮新定的策划写入策划设计，新定的美术写入美术设计。不要整篇重写，不要改其他模块。

目录里还没有 `美术设计.md` 时补上这一份。没有画面就写「本模块无画面」。已有的这一份只改正波及的段落。

新模块如果整段是这轮用 AI 做的，策划和已经定下的美术按这轮对话写全，不留 `spec:design-gap`，除非还有没定的部分。没有画面就写「本模块无画面」。

用户说「补全模块规格」时不要走当轮更新：那是把模块写成可拿走的说明书，必须走首稿加反推循环。

## 手动补全

用户说「补全模块规格」，或运行了 `pmem spec complete`（或旧名 `pmem spec fill`）时，先跑 `pmem spec complete`。它列出的空标记还在的模块，以及已经去掉空标记但反推仍推不出契约的模块，都按首稿写满栏目（含入参和出参字段闭集、失败条件、配置与环境变量、生成物、须按字面抄的原文、依赖规格），再走反推循环，直到已实现的对外契约能从规格还原到至少九成八。代码和资源里看得到的都写上。独立于代码的完整策划稿、完整美术说明写「尚未写入」，并保留 `spec:design-gap`。没有画面就写「本模块无画面」。反推已经够用的段落不要整篇重写。一句一行。

## 写完

`updated` 改成今天。然后 `pmem spec index` 刷新目录。文首事实由命令维护，不要手改那一段。目录的留空列标出策划或美术仍留空，以及旧稿缺了这两节；这不改变空标记是否去掉，也不代替反推循环。
