根因：闸门只认 `pmem <子命令>` 和 `uv run pmem <子命令>` 两种固定写法。命令写成 `uv run --extra embed pmem record ...` 时，`pmem` 前面多了参数，就整条认不出来。

后果：
- 这次写入不登记，结束时仍提醒“还没有写研发记忆”（误报）；
- 也不记 record_call 事件，收益报告里“提醒后写了”漏算；
- 同样写法的 `pmem search` 也不算“已查过”，改代码时会被多拦一次。

证据：一个对话里用这种写法写了 5 个模块的记忆，会话状态 cli_recorded 一个都没有，事件日志里也没有 record_call，stop 照样提醒 feature.Curation。

处理：只要命令以 uv / uvx / pipx / python 等启动器开头，就在后面的参数里找 `pmem <子命令>`；`echo pmem search` 这类非启动器开头的仍不算。

排查同类误报时：先在会话状态文件（缓存目录 sessions/<对话id>.json）里看 cli_recorded，再用 cli_args 解析当时的原始命令。
