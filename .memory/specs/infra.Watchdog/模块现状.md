## 模块现状

入口：`pmem serve [--root] [--worker]`。
默认带看门狗。
手动调试服务本身时加 `--worker`。
`server.watchdog: false` 关闭看门狗，本进程直接跑 MCP。
`--root` 默认空，解析顺序与 MCP 相同。
`serve` 不做配置预检，配置坏也能启动。

必须保持：Cursor 只连看门狗这一个 stdio 进程，崩溃后客户端连接不断。
子进程命令用当前解释器加 `-m pmem.cli.main`。
超时默认 120 秒，最多放到 960 秒，避免首次下载模型和建索引被反复杀掉。
取消的请求不再计时。
健康报告只统计崩溃和超时，不统计因代码更新而重载。
看门狗开关和超时改了之后，要在 Cursor 里重启 MCP 才生效。

一轮例子：子进程在一次 search_memory 期间被杀掉。
客户端先收到错误「正在自动重启，请重试」；看门狗用缓存的 initialize 重新握手（内部 id 的响应不回传）；下一次同一工具在 1 到 2 秒内正常返回。

测试在 `tests/test_watchdog.py`，用假子进程覆盖转发、崩溃重握手、超时加倍、取消、退避、空闲重载和客户端断开。
全量测试在机器忙时偶发卡在握手夹具上，闲时稳定；不影响真实 `pmem serve`。

单独拿走时还要带走的依赖规格：
feature.Tools（MCP 工具实现）。
infra.Model（server.watchdog、server.request_timeout 缺省 120）。
feature.Metrics（重启记事件）。
infra.Common（serve 子命令登记与 root 解析）。
