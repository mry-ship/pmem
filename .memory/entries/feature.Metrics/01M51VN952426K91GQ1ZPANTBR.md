决定：收益报告的“改代码前被提醒先查，随后真的查了”按 search_call 和 mcp_search 两种事件计算。

原因：闸门改为 MCP 检索返回结果后才登记“已查过”，preToolUse、beforeMCPExecution 不再写 search_call，MCP 检索只在 afterMCPExecution 写 mcp_search（带模块和返回的记忆 id）；
终端 pmem search 仍在执行前写 search_call（via=cli）。
如果只统计 search_call，MCP 检索就不会算作“提醒后查了”。

附带效果：以前一次 MCP 检索会记两条 search_call（preToolUse 和 beforeMCPExecution 各一条），本仓库日志里 36 条 search_call 只对应 18 次实际检索。
现在每次检索只记一次。
旧日志里的重复不影响这项转化率，因为它只看拦截之后有没有对应检索。
