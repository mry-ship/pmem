需求：用户要求 pmem init 自动启用项目级 MCP（非用户级），覆盖 Cursor / Claude Code / Codex。
后又反馈“别的项目 init 后 Cursor 的 pmem MCP 没拉起来、重启也不起”：根因是 Cursor 运行时用内存副本覆盖外部进程写进 state.vscdb 的批准（见本议题 conclusion 01M6R0R673X1SEQZ2BRD8D49Z9）。

必须保持的行为：
- 项目 MCP 仍落在各项目配置文件；
  Cursor 写本机 approvedProjectMcpServers（哈希对齐 Cursor，含未解析 ${workspaceFolder}，有符号十六进制、负数带负号）；
  Claude 项目 enabledMcpjsonServers 含 pmem；
  Codex 项目 trust_level=trusted。
- 禁止写用户级 ~/.cursor/mcp.json。
- pytest 下默认不写本机状态（_skip_local_enable 先行；PMEM_SKIP_MCP_ENABLE=0 才测写入）。
- 新增：Cursor 运行时不自动批准。
  新增 cursor_running()（Windows tasklist /FI "IMAGENAME eq Cursor.exe" /NH，走 no_window_kwargs 不弹框；macOS/Linux pgrep -x Cursor/cursor；查不出返回 False）。
  enable_cursor_project_mcp 在找到 state.vscdb 后若 cursor_running() 为真，则不写库，返回“检测到正在运行，写入会被 Cursor 覆盖；
  退出 Cursor 后重跑 pmem init，或 设置→MCP 手动启用后 Reload Window”。
  doctor 的“尚未批准”在运行时追加同样提示；
  NEXT_STEPS[cursor] 文案同步。
  Claude/Codex 不受影响。

入口：src/pmem/generate/mcp_enable.py（cursor_running、enable_cursor_project_mcp、setup_* 调用）；
doctor 检查批准；
