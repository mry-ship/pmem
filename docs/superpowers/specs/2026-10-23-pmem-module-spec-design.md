# pmem v0.6 模块规格设计

日期：2026-10-23　状态：骨架、技能和回合提醒已实现（进度见 [Issue #16](https://github.com/mry-ship/pmem/issues/16)）。模块改名、合并时规格文件还不会跟着搬。

## 1. 背景与目标

记忆按议题记下模块是怎么变过来的：根因、排除过的方向、必须保持的行为。它不给出一份「这个模块现在是什么样」的全文。

要补的是另一条线。每个已登记模块一份当前规格，单独拿走这一份，就能在另一个工程里把这个模块重新做出来，也可以拿去当别的设计的输入。不拷贝工程源码。

目标：

1. 与 Wiki 平级，一个模块一份，放在 `.memory/specs/`，进版本库。
2. 每份写全四类：策划设计、美术设计、程序设计、模块现状。验收标准是单拿这一份就能重做该模块。没有画面的模块，美术设计写「本模块无画面」即可。有画面的把风格、布局、状态、动效和资源规格写进来，规格才够拿去重做画面。
3. 旧模块先做一次首稿。程序和现状按代码里的实现写。策划只写已经体现在代码或资源里的数值、边界、表现、规则。没留下的完整策划稿留空，以后扫代码也补不回来。美术同样只写资源里量得到的风格、布局、状态、动效和资源规格；没留下的完整美术说明留空。没有画面的写成「本模块无画面」。
4. 更新不按时钟。某一轮改了该模块，或这轮定了新策划、新美术，这一轮结束前更新这一份一次。同一轮多次改动合并成一次。程序和现状只改正波及的段落，当轮策划和美术写入并保留，其他模块和其他段落不动。没有画面的不补编美术。
5. 新模块整段由 AI 做成时，策划和已经定下的美术都在当轮对话里，当轮写入才算留下来。没有画面就写「本模块无画面」。
6. 规格上不做记忆那种过期核对，不标「需核实」。

不做：

- 把规格并进 Wiki，或把 Wiki 加厚来充当规格。
- 用现有 `pmem scan` 生成正文。它只输出目录概览和提交热度。
- 定时全量重写、每次写一条记忆就重写、像 Wiki 一样整篇覆盖。
- 用规格代替研发记忆。坑、排除项、必须保持的行为仍然用 `record_memory` 写。

版本：本设计定为 v0.6，安装包版本 0.6.0。原先占着 v0.6 的类型安全与规则化顺延为 v0.7，范围不变，仍见 `2026-10-21-pmem-typesafe-design.md` 与 Issue #15。

## 2. 现状

| 已有能力 | 位置 | 和规格的差别 |
|---|---|---|
| Wiki | `generate/wiki.py`，`pmem wiki` | 从记忆推出，写入后整页重写，标需核实，默认 `.gitignore` |
| 目录扫描 | `scan/lite.py` 的 `run_scan` | 只列目录和热度，供划分模块 |
| 结束提醒 | `hooks/reminders.py` 的 `on_stop` | 已能知道本轮哪些模块改过、要不要写功能记录 |
| 闸门忽略 | `config` 的 `gate.ignore` 含 `.memory/**` | 改 `.memory/` 不会记进 `edited_files`，规格写没写过要单独认 |

原则不变：命令行做确定性的事，要读懂代码才能写的正文交给 Agent 技能。

## 3. 设计

### 3.1 目录

```
.memory/specs/index.md
.memory/specs/<模块名>/index.md
.memory/specs/<模块名>/策划设计.md
.memory/specs/<模块名>/美术设计.md
.memory/specs/<模块名>/程序设计.md
.memory/specs/<模块名>/模块现状.md
```

- 不放 `.gitignore`。规格是记录，要随 `.memory/` 提交。
- 一个已登记模块一个目录，四份正文分开。给美术时只拷 `美术设计.md`。这份里不放上下级和代码路径；那三行只在该目录的 `index.md`，由命令维护。
- 目录名只用合法模块名，解析后必须落在 `spec.dir` 里面。非法名字、`..`、符号链接的目录或正文都拒绝。
- `spec.dir` 指到项目外时，`pmem spec` 返回 2，不写文件。
- 含子模块。父模块的四份不复制子模块的正文。总目录按现有层级缩进，链到各模块的 `index.md`。
- 以前的单文件 `<模块名>.md` 在 `init` 或 `index` 时拆进目录，正文按四个标题切开，不改写句子。目录已经存在时不拆。

### 3.2 一个模块目录里有什么

上下级和代码路径由命令写在 `<模块>/index.md`。四份正文由 Agent 维护，各自一份，刷新事实时不改这四份。

`策划设计.md`、`美术设计.md`、`程序设计.md`、`模块现状.md` 的文件名固定。程序和现状还没写完时，文件里放 `<!-- spec:empty -->`。策划里，首稿看不到的完整设计放 `<!-- spec:design-gap -->`，并写一句话说明这里是留空。以后补上某段时，只去掉已经补上的那处标记。

美术有画面时写风格、布局、各状态的画面、动效、资源规格；看不到的完整美术说明同样留 `<!-- spec:design-gap -->`。没有画面的写成「本模块无画面」，不放 `<!-- spec:empty -->`。缺了美术那一份，或里面仍留空，不算首稿未完成。`--check` 仍只看程序和现状这两份。图片和模型本身不放进 markdown。

四份都写成可以脱离本仓库阅读的文字。正文不靠「请打开某文件」来完成说明。一句一行，句号或分号留在行尾，换一件事再空一行。

总目录 `index.md` 由 `pmem spec index` 生成，列出全部已登记模块、完成状态、策划和美术是否仍留空、最近 `updated`。旧目录缺了策划或美术那一份时，留空列标出，但不把模块改判成首稿未完成。它是目录，不是第二份正文。合并冲突时重新运行命令，不要手改。`index` 不补缺失的正文；`init` 才给还没有的那一份写骨架，已有文件不覆盖。

### 3.3 谁写什么

命令行（确定性）：

| 命令 | 作用 |
|---|---|
| `pmem spec` | 列出每个已登记模块：无文件、首稿未完成（程序或现状仍有 `spec:empty`）、已有规格。废弃模块单独标出，不要求补 |
| `pmem spec init` | 只为还没有文件的模块写骨架：文首事实、四节标题、程序和现状的空标记、策划和美术的留空标记。不写正文。已有文件不覆盖。`pmem init`、`pmem sync --apply`、以及自动登记真正写入新模块时，都会做这一步 |
| `pmem spec complete` | 补全模块规格的入口：和 init 一样只补还没有的骨架，然后列出首稿还没写完的模块。有未完成时返回 1。完整正文由 `pmem-spec` 按代码写到九成八。看不到的策划和美术留空，不编造。`fill` 是同一条命令的旧名 |
| `pmem spec index` | 重写总目录，并只刷新各模块目录里的 `index.md`（上下级和代码路径）。四份正文原样保留，也不补还没有的那一份 |
| `pmem spec --check` | 有模块还没有完成首稿时返回 1，供需要时自查。默认的 `pmem spec` 只列出，返回 0 |

技能 `pmem-spec`（判断性，`pmem init` 写到各 Agent 的技能目录）：

- 首稿：读该模块 `paths` 下的代码和资源。写程序设计（结构、数据、接口、依赖、状态、关键流程）和模块现状（按这份就能重做的当前细节）。策划只写看得到的数值、边界、表现、规则。看不到的保留 `spec:design-gap`。有画面时写美术设计（风格、布局、状态、动效、资源规格），看不到的完整美术说明同样留 `spec:design-gap`。没有画面就写成「本模块无画面」。写完程序和现状后去掉这两节的 `spec:empty`。美术节不用这个空标记。
- 当轮更新：只改正波及的程序和现状段落。这轮新定的策划写入「策划设计」，新定的美术写入「美术设计」，已有内容保留。不要整篇重写，不要改其他模块。目录里还没有 `美术设计.md` 时补上这一份；没有画面就写「本模块无画面」。父模块不写子模块的正文。正文自己能读懂，不靠「请打开某文件」。
- 手动补全：用户说「补全模块规格」或运行 `pmem spec complete`（或旧名 `fill`）时，对列出的每个未完成模块按首稿写全到九成八。命令本身不写正文。
- 新模块若整段是这轮用 AI 做的：策划和已经定下的美术以这轮对话为准写全，不留 `spec:design-gap`，除非用户明确还有没定的部分。没有画面就写「本模块无画面」。
- 写之前用 `search_memory` 读该模块的功能记录，把「必须保持的行为」写进现状。正文仍是规格，不把记忆条目贴成清单。四节写的是模块现在的设计，不写「这一轮只新增」「本轮不重写」。还没写入的部分留 `spec:design-gap`，并写「尚未写入」。
- 一轮里同一模块改了多处，合并成这一次更新。

用户说法：「按 pmem-spec 补模块规格」「更新这个模块的规格」。

### 3.4 更新怎么触发

不设定时任务，也不在写入记忆后自动改规格。

`spec.reminder` 默认关闭。设为 true 时，回合结束和功能记录用同一份「本轮真正改了行为的模块」名单（`Reminders._record_required`：不计废弃模块，不计 `gate.record_exempt`）。其中还没写过对应规格文件的，提醒一次。回复里对该模块声明了「无需记录」的，规格也不提醒。

`.memory/**` 在闸门忽略名单里，写规格不会进入 `edited_files`。因此在 `_post_tool` 里单独认：写入路径落在 `spec.dir` 下、文件名是某个模块的规格时，记入本对话状态 `spec_written`。忽略名单继续挡住它，不把它当成业务改动，也不为此再要求写一条功能记录。

提醒文案要求按 `pmem-spec` 更新那一份：程序和现状只改正波及的段落，本轮新策划和新美术写入并保留，无画面的模块美术节写「本模块无画面」，目录里还没有 `美术设计.md` 时补上这一份，不要整篇重写。每个模块一轮只提醒一次。

只改了图片或资源、模块登记的代码路径没有变化时，这份名单里没有该模块，回合提醒不会响。这种回合仍由人说「更新这个模块的规格」。资源目录若登记在该模块的 paths 里，改这些文件会照常提醒。

配置：

```yaml
spec:
  dir: .memory/specs
  reminder: false   # 默认不提示。改成 true 后回合结束提醒更新规格；gate.mode 为 off 时不提醒
```

`spec.dir` 和 `spec.reminder` 有缺省值，提醒缺省是关。首次 `pmem init` 生成配置时，在终端里询问是否开启：输入 y 才写成 true，直接回车保持 false。没有终端时不询问，保持关闭并打印改法。已有项目的 `config.yaml` 不被 `pmem init` 改写，再次运行也不再问，也不会被补上一份 `spec` 段。缺了 `spec.reminder` 时，`Config.load` 在读取时并入 false，因此没写过这项的旧项目升级后不再弹出规格提醒。文件里已经写成 true 的仍提醒，已经写了的 `spec.dir` 保持原值。

### 3.5 和记忆、Wiki 的关系

- Wiki 继续只浏览记忆，生成逻辑不改。
- 规格更新不调用 `write_wiki`，写记忆也不触发规格重写。
- 功能记录是约束：规格要遵守它，但不替代它。
- 模块改名、合并时，规格文件跟着记忆一起搬（`migrate rename` / `merge`）。拆分、废弃时在 `pmem spec` 的输出里说明，不自动改四节正文。

## 4. 实现顺序

细则、文件和测试见 `docs/superpowers/plans/2026-10-23-pmem-module-spec.md`。

1. 骨架、目录、`pmem spec` / `init` / `complete`（`fill` 旧名）/ `index` / `--check`。正文写到九成八。
2. `pmem-spec` 技能。
3. 回合结束提醒，以及 `spec_written` 的登记。
4. 命令写进使用手册、架构说明和总设计第 11 节。路线表在立项时先改。

## 5. 验收

- 每个已登记、未废弃的模块一个目录，里面四份；`pmem spec init` 再次运行不覆盖已写正文。
- 只拷需要的那一份，例如只把 `美术设计.md` 给美术。四份正文都不依赖打开本仓库其他文件才能读懂。没有画面的，美术那一份是「本模块无画面」。
- 刷新模块 `index.md` 或重写总目录之后，四份正文不变；已写入的策划和美术在只改程序的更新后仍在。总目录的留空列能看出策划或美术仍留空，以及缺了那一份；这不改变 `--check`。
- 本轮改了模块却没写规格时，回合结束提醒一次；声明无需记录、或只改了免记录文件时不提醒。只改了未登记进模块路径的资源时不提醒。
- `spec.dir` 指到项目外、或模块名会写出目录时，命令拒绝，不落文件。
- Wiki 的页面规则和生成时机不变。
