## 模块现状

入口是四条命令：

- `pmem spec`：列出每个未合并模块的状态。
- `pmem spec init`：缺哪一份才写哪一份骨架。输出「规格骨架：新写 N，已有 M，目录 …」。
- `pmem spec fill`：同样只补骨架，并列出首稿没写完的模块。有未完成时返回 1。没有已登记模块时只说明还没到这一步，不说首稿都已写完。正文不由这条命令生成。
- `pmem spec index`：刷新各模块 `index.md` 和总目录。留空列标出策划、美术仍留空，或还没有那一份。四份正文不被改写。
- `pmem spec --check`：有未完成首稿时返回 1。
- `pmem init`：模块已登记时顺手补骨架，下一步提示「补全模块规格」。
- `pmem sync --apply` 和自动登记真正写入后：只补还没有的骨架。

新骨架里，策划那一份写着「首扫未从代码中看到的完整策划，此处留空。
」美术那一份写着：无画面就写「本模块无画面」；
有画面时写风格、布局、状态、动效和资源规格，看不到的说明保留留空标记。
程序和现状各有一个空标记（spec:empty）。
上下级和代码路径在模块 `index.md`。
再次 init 时，已有正文保持原样。

符号链接的模块目录不覆盖，命令返回 2。
`spec.dir` 配成项目外（例如 `../outside-specs`）时不创建目录，返回 2。

测试在 `tests/test_spec.py`。
必须保持：init 不覆盖已写正文；
index 只改模块索引和总目录；
美术那一份不带代码路径；
废弃模块不计入 `--check`。
