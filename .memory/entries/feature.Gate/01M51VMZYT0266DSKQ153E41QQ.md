结论：闸门识别终端写文件，原先漏掉两类写法，已补上。

1. 再套一层终端的命令：powershell/pwsh -Command 或 -c、-File x.ps1，cmd /c、/k，bash/sh/zsh -c，直接运行的 .ps1/.bat/.cmd/.sh（含 & ./x.ps1）。现在取出里层的命令或脚本内容，再按同样规则递归解析（最多 3 层）。另外补了 Tee-Object 和 New-Item 的别名 ni。注意：按 ; 拆语句时会把引号里的命令拆开，两半各自仍能被识别，不要为此改成严格的引号解析。

2. 变量或脚本里拼出来的路径（如 Path('src', 'Jig'+'saw')、Set-Content $p），事前无法得知目标。改为事后核对：命令在跑脚本或内联代码、或者解析出的目标含 $ % {，并且是 Git 项目时，preToolUse 先记下未提交文件快照（git ls-files -m -d -o --exclude-standard，路径 → mtime 和大小），postToolUse（matcher 需含 Shell，Claude Code、Codex 需含 Bash）再取一次比对。变化的文件记为已编辑，结束时照常提醒写记忆；改到没查过的、有记忆的模块，就用 additional_context 立即提醒补查并列出排除项和风险。每个模块每个对话只提醒一次。

限制：事后核对只能提醒，拦不住；SVN 和无版本库项目不做；用 Write 工具与终端命令并行改的文件，也会被算作终端改的。
