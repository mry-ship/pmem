更正：旧记忆说 --rename 的匹配顺序是“路径#函数 精确匹配 > 整个文件 > 目录前缀”，实际只有“精确匹配优先”成立；
文件规则和目录规则之间没有优先级，按参数顺序取第一个命中的。
实测先写目录规则时，后面的文件规则不生效。
所以同时给目录和其中某个文件改名时，把文件规则写在前面。
仍有效：pmem anchors --rename 旧=新 [--apply]（可写多次）在代码文件或目录改名、函数搬到别的文件后批量改写所有记忆的关联代码（含已替代、已归档的，保持历史可追溯），默认只预览；
带 # 时两边都要带；
预览里列出改写后对不上的（新文件不存在、找不到该函数）。
原因：已提交的记忆不能用 draft_id 覆盖，原先代码一搬家只能逐条写 correction。
注意：改写后新文件的提交记录会让这些记忆标“需核实”，核对后 pmem confirm；只搬了部分函数时要用 路径#函数名 逐个写，不能整文件改。
