现象：pmem init 自动项目级批准 Cursor 的 pmem MCP，重启 Cursor 后仍显示未批准（doctor 报“Cursor 尚未项目级批准 pmem MCP”），MCP 起不来。

排查实测（本机 Cursor-Project-Memory）：
1) enable_cursor_project_mcp 函数逻辑没问题：在干净的 state.vscdb 上能正确写入 project-0-<名>-pmem:<哈希> 到 approvedProjectMcpServers，且 key 与 cursor_approval_key 一致（合成 DB 实测 MATCH=True）。
2) 配置哈希也没问题：Cursor（JS）用有符号 toString(16)，负数带前导负号——其自写的 project-0-TileMatch-playwright:-433220a0 就是负号，说明 pmem 保留有符号十六进制是对的，不能改成无符号（tests/test_mcp_enable.py 已钉住这条）。
   一度误以为要按 (h>>>0) 无符号输出，实测推翻。
3) state.vscdb 是 WAL，Cursor 运行时 pmem 的写锁 0.01s 就拿到、不阻塞不报错，写能落盘。

根因（看代码看不出）：Cursor 启动时把 approvedProjectMcpServers 读进内存，之后设置变化或退出时用内存副本整体写回 state.vscdb，覆盖掉 pmem init 期间写进去的批准。
所以 init 写成功 → Cursor 下次 flush 覆盖 → 批准消失 → 重启也起不来。
症状“init 当下能用、重启后没了”正是这个。

解法方向（未实现，待定）：init 写 Cursor 批准不能在 Cursor 运行时做；可选：
- doctor/init 检测到 Cursor 进程在跑就提示“先退出 Cursor 再 init，或手动在 设置→MCP 开 pmem 后 Reload Window”；
- 或放弃写 state.vscdb，回到让用户在 Cursor UI 里点一次（一次性）。
Claude/Codex 不走 state.vscdb（~/.claude.json、~/.codex/config.toml），不受此影响。

入口：src/pmem/generate/mcp_enable.py#enable_cursor_project_mcp；自检 src/pmem/cli/doctor_cmd.py（报“尚未项目级批准”那条）。
