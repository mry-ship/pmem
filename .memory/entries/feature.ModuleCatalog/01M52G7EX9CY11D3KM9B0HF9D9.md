决定：pmem migrate 提供 rename / merge / tidy，默认只预览，--apply 才写 modules.yaml 并搬记忆文件。
- rename A B：键名原位替换，A 的完整名登记为别名；旧短名只被 A 使用时也登记为别名（正文提及与短名解析才认得）。B 的完整名或短名已被其他模块占用时拒绝，避免短名歧义；B 是冷候选时拒绝并提示改用 merge。指向 A 的 merged_into 和 parent（modules 与 candidates 里）一并改成 B。
- merge A B：A 的 paths/aliases/entities/components/variants 并入 B，A 只留 description 和 status: merged_into:B（别名必须从 A 移走，否则短名在两个模块里同时出现会报歧义）。A 是未登记模块（写入时自动新建、笔误）或冷候选时，改为把 A 登记为 B 的别名，冷候选的路径并入 B 并从 candidates 删除。
- tidy：所有记忆文件中模块名经解析后不等于自身的（已改名、已并入、写成别名），搬到正式模块目录并改写 module 字段。rename/merge 执行时自动做同样的搬迁。目标目录已有同名文件（重复 id）时在预览阶段就拒绝，不覆盖；Windows 上只差大小写的目录视为同一位置，只改写 module 字段。

原因：merged_into 只转发模块名，索引按记忆文件里的 module 字段过滤，不搬文件旧记忆就查不到。

风险：没有保留注释的 YAML 库，重写时只保留文件开头的注释块，中间的注释会丢，预览时会提示丢失行数；先写 modules.yaml 再搬文件，搬到一半失败（如 svn mv 出错）时提示排除后运行 pmem migrate tidy --apply 补完。队友在迁移前写到旧模块名下的记忆，拉取后需要再跑一次 tidy（pmem health 会列出）。
命令行用法：migrate 是嵌套子命令，--root 和 --apply 要写在子命令之后（pmem migrate rename A B --root X --apply）。
