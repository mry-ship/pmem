## 策划设计

每个已登记模块一个目录，放在 `.memory/specs/<模块>/`，随仓库提交，与 Wiki 分开。
Wiki 只浏览记忆。
四份正文分开：策划设计、美术设计、程序设计、模块现状。
给美术时只拷 `美术设计.md`。
上下级和代码路径只在该目录的 `index.md`。

四份写的是模块现在的设计，不写「这一轮只新增」这类过程说明。
命令行不写这四份的正文，只负责骨架、模块索引和总目录。
正文由 `pmem-spec` 技能写。
验收不是「有没有空标记」，而是：单独拿走这套规格，在别处能否做出相似甚至一样的实现。
一样要求词表、协议原文、字段名、错误码和数字能还原；相似允许把流程映射到新工程的命名和路径。
补全时必须走反推循环：合上代码只根据规格重做，推不出的再抄进规格，直到没有缺口。
要复用实现就拷整个模块目录，并把所有权里点名的依赖规格一并带走。
给某一工种可以只拷那一份。
已经去掉空标记但仍反推不过的，缺哪一类补哪一类。
`pmem spec complete` 是补全入口：先补还没有的骨架，再列出首稿没写完的模块；`fill` 是旧名。
用户对 Agent 说「补全模块规格」或运行这条命令时，技能按代码把这些模块写到九成八。
看不到的策划和美术写「尚未写入」并留空。
还没写入的部分留设计留空标记，并写「尚未写入」。

四份正文一句一行，句号或分号留在行尾。
换一件事再空一行。

旧模块的首稿：程序和现状按代码里的实现写。
策划只写已经体现在代码或资源里的数值、边界、表现、规则；
看不到的完整策划留设计留空标记（spec:design-gap）。
有画面时，美术写风格、布局、各状态的画面、动效和资源规格，看不到的完整美术说明同样留空。
没有画面的整节写成「本模块无画面」。
整段由 AI 新做的模块，策划和已经定下的美术在当轮写全。

更新不按时钟。
某一轮改了该模块，或定了新策划、新美术，这一轮结束前更新这一份一次。
程序和现状只改正波及的段落，已写入的策划和美术保留。
规格上不标「需核实」。
美术节不放空标记（spec:empty），缺了它也不算首稿未完成。

`spec.dir` 必须留在项目内。
页面文件名只能是合法模块名，不能顺着 `..` 或符号链接写出目录。
废弃模块出现在列表里，但不算未完成。

还没做：`migrate rename` / `merge` 时规格文件跟着搬。

已实现行为的策划以代码可见规则为准。
