更正：旧记忆说“Hooks 不再直接调用 pmem，改为经包装脚本调用”，不对：Cursor 的 hooks.json 里只有 sessionStart 经 .memory/bin/pmem-hook，beforeSubmitPrompt、preToolUse、postToolUse、stop 等仍直接写 pmem hook …。
没装 pmem 时这些 Hook 起不来、按 failClosed=false 静默放行，只有 sessionStart 那一条能告诉 Agent 提醒用户安装。
包装脚本里 pre-tool、prompt 的分支实际不会被调到。
仍有效：包装脚本 sh 版无扩展名、LF；
Windows 版 pmem-hook.cmd、CRLF、纯 ASCII；
附 .gitattributes 固定换行，Git 下登记可执行位。
找得到 pmem 就转交；
找不到时 sessionStart 返回 additional_context 提示安装。
规则里保留：工具必须来自 pmem；
MCP 不可用时改用终端 pmem search --module <模块> --brief / pmem record；
pmem 也找不到时告诉用户先安装。
Claude Code 另有 onFailure: continue，Hook 起不来时放行。
风险：未在真实 Cursor 里验证 sessionStart 提示送达；旧项目要重新 pmem init，doctor 对缺包装脚本报警告。
