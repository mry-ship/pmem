决定：用 draft_id 覆盖记忆时，没传的 supersedes / anchors / aliases 沿用草稿原值，传了才替换。
MCP 的 record_memory 把空列表也当作没传；
命令行默认没传，只写参数名不跟值（如 --supersedes）表示清空。

原因：原先覆盖时不传就清空。
替代关系一丢，被替代的旧记忆重新变成现行，检索时新旧结论同时出现且不易察觉（2026-10-16 覆盖 feature.Gate ShellParse 草稿时实际踩到）。
MCP 侧 draft_id 常由闸门自动注入，Agent 不知道自己在覆盖，模型又习惯给可选数组填 []，所以 MCP 不支持用 [] 清空；
要清空就新写一条或用命令行。

影响范围：只影响带 draft_id 的写入；新建记忆不变。风险：真想去掉草稿的替代关系或别名时，MCP 做不到，需要走命令行。
